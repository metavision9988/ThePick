## 2. 결정 사유 (진산님 직접 발언)

원문 (2026-04-25):

> "소형 ai 모델 도입은 지금 단계에서 검토만 하고...
> 향후 미래에 도입할 것이라는 것을 고려만 하고
> 즉 시스템 확장에 반영만 해주고
> 지금은 설계나 구현을 미루자.
> 지금 시점에서 시기상조일 거 같아.
> 아직 한국어기능이 미흡하고..
> 현재 국가차원에서 모델개발중이니까..
> 1년 뒤면 충분하리라 생각해서.. 그때 재설계를 해보자."

### 2.1 4가지 결정 근거

1. **시기상조** — 2026-04 시점에 손해평가사 도메인에서 SLM이 Claude Haiku
   대비 합격 수준에 도달했다는 실측 증거 부재. [B-6A] 검증조차 시작 전.
2. **한국어 기능 미흡** — Llama 3.2 3B / Qwen 2.5 3B 모두 공식 한국어 지원
   언어가 아니거나 부분 지원. EXAONE 3.5는 연구용 라이선스. HyperCLOVA X
   Seed 1.5B는 파라미터가 작음.
3. **국가 차원 모델 개발 중** — LG AI / NAVER / KT / SKT의 한국 소버린 AI
   컨소시엄 진행 중. 1년 후 한국어 특화 오픈웨이트 모델의 보편화 가능성
   높음. 지금 잘못된 모델에 결합하면 매몰 비용 발생.
4. **AI 도구 진화 기대** — 1년 뒤 Claude를 포함한 코딩 AI가 더 똑똑해져
   현재 막히는 설계 문제·운영 문제도 더 잘 해결할 가능성.

### 2.2 본 결정이 합리적인 이유 (검증)

- **Year 1 비용 영향 미미.** 본 결정으로 절감되는 비용보다, 이 결정이
  Year 1 핵심 엔진(Graph RAG, Formula Engine, FSRS) 개발 집중도를 높이는
  효과가 큼.
- **Reality Anchor 원칙 정합.** "이것이 불가능할 이유 3가지" 중 시나리오
  A(환각 유입)·시나리오 C(라이선스 충돌)가 본 결정으로 동시 회피.
- **PITR(기술 선택지 비교) 원칙 정합.** 첫 번째로 떠오른 방법(Llama 3.2
  3B를 Workers AI에 도입)을 즉시 채택하지 않고, 시장 성숙을 기다리는
  것은 PITR의 실천.
- **단일 벤더 원칙 보호.** ADR-006(Cloudflare 단일 벤더) 예외 조항을
  당장 활용하지 않으므로 단일 벤더 단순성 유지.

## 4. 동결되지 않는 항목 (계속 살아남는 자산)

본 결정의 핵심: **"감안하여 개발"의 7원칙 중 일부는 SLM 도입과 무관한
일반 헥사고날 원칙이므로, AI 보류와 분리해서 유지한다.**

### 4.1 살아남는 7원칙 중 5개 (일반 개발 원칙으로 전환)

| 원칙                                                               | 살아남는 이유                                                                    |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| **원칙 1**: 해설 생성 함수를 인터페이스로 정의                     | 헥사고날 원칙 그 자체 (도메인 ↔ 인프라 분리). AI 없이도 가치 있음.               |
| **원칙 4**: Graph RAG 결과를 사용자 직접 노출 가능한 형태로 구조화 | Year 1에 가장 가치. AI 없이 description 그대로 화면에 띄움.                      |
| **원칙 5**: 정답/산식/법조문은 절대 AI 경로에 두지 않음            | Hard Rule 2/5 그 자체. AI 안 쓰는 동안에도 코드 분리는 유지.                     |
| **원칙 6**: 사용자 피드백 수집 훅을 미리 UI에 삽입                 | Year 1에도 "도움됐어요" / "신고" 버튼은 유의미. AI 없이도 콘텐츠 품질 측정 가능. |
| **원칙 7**: Feature Flag 시스템                                    | AI 무관하게 일반 운영 도구. Phase 2에 도입 가치 있음.                            |

### 4.2 보류되는 7원칙 중 2개 (AI 활성화 시점에 부활)

| 원칙                                                            | 보류 이유                                                                 |
| --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **원칙 2**: 모든 AI 진입점은 단일 경로(`/api/exams/:exam/ai/*`) | AI 자체가 없으므로 라우트 예약도 불필요. 1년 뒤 부활.                     |
| **원칙 3**: UI에 "AI 자동 생성" 배지 자리 미리 확보             | AI 없이 배지 자리만 잡아두는 것은 디자인 부담. Year 1 UI는 깔끔하게 시작. |

### 4.3 데이터 수집 인프라 — 부분 살림

본 결정의 **가장 미묘한 부분**: 등급 A/B/C 데이터 수집 시스템(v1.1 §4)을
어디까지 살릴지.

**Year 1 Phase 2~3에 살릴 것:**

- `user_feedback` 테이블 (user_ai_feedback이 아니라 일반 콘텐츠 피드백)
  - 사용자가 해설/플래시카드/암기법에 "도움됐어요" / "어려워요" / "신고"
  - AI 무관, **사람이 만든 콘텐츠 품질 측정** 용도
- 신고 버튼 UI + 사유 입력
- 진산님 모니터링 대시보드 (자주 신고 받은 콘텐츠 리스트)

**Year 1에 보류할 것:**

- `lora_training_candidates` 테이블 (LoRA 훈련 후보)
- `lora_datasets` 테이블 (학습 세트 메타데이터)
- 자동 승격 파이프라인 (등급 A → B → C)
- PIPA 동의 UI 중 "AI 학습 활용 동의" 항목

**핵심 통찰:** 일반 콘텐츠 피드백 인프라는 LoRA 훈련 데이터 수집 인프라의
**기초**이다. Year 1에 일반 피드백 인프라가 1년치 운영되면, 1년 뒤
"AI 학습 활용 동의" 항목 추가만으로 등급 A 데이터 수집이 자동 시작 가능.
**우회로지만 자연스럽다**.

### 4.4 Constants/법령/산식 분리 원칙은 더 강해짐

본 결정으로 인해 Hard Rule 2(LLM 산식 계산 금지) / 5(Constants 직접 조회)는
**Year 1 내내 더욱 강력하게 적용**된다. AI 자체가 없으므로 위반 가능성이
물리적으로 0. 이 기간 동안 Formula Engine과 Constants Service의
순수성을 확보하는 좋은 기회.

## 5. 1년 뒤 재검토 트리거

다음 중 하나라도 충족 시 즉시 본 동결을 해제하고 v1.1.1 작업 재개를
검토:

### 5.1 시간 트리거 (기본)

- **2027-04-25 또는 그 이전.** 메모리에 기록되어 있으므로, 진산님이
  "쪽집게 AI 모델 어떻게 됐지?" 등 물으면 자동 트리거.

### 5.2 시장 트리거 (조기 해제 가능)

- 한국 소버린 AI 컨소시엄에서 **상용 자유 라이선스의 한국어 특화 3B~7B
  오픈웨이트 모델** 공개
- EXAONE 3.5 또는 후속 버전이 **상용 라이선스를 명시적 무료/저비용** 공개
- HyperCLOVA X Seed 3B 이상 오픈웨이트 공개
- Cloudflare Workers AI에 **한국어 특화 모델** 정식 등재
- 한국 자격시험 SaaS 경쟁사가 **온디바이스 AI 마케팅** 본격 시작

### 5.3 내부 트리거

- 베타 운영 중 **사용자가 "AI 재설명/힌트"를 명시적으로 요청**하는 패턴
  3개월 누적
- 콘텐츠 인간 작성 비용이 **시간/예산 한계**에 부딪힘 (LoRA 자동 생성
  필요성 발생)
- 멀티시험 확장(Year 2 Phase 4) **착수 직전** — 시험별 LoRA 어댑터
  설계는 본 시점에 자연스럽게 부활

### 5.4 외부 차단 트리거 (해제 거부)

- 한국 PIPA 또는 후속 법령에서 **"학습된 모델 파라미터의 개인정보 파기"**
  의무가 강화 → 본 동결을 더 연장
- Cloudflare Workers AI deprecation 또는 가격 급등 → 대안 부재 시 연장

## 7. 1라운드 검토 압축 (H1~H8)

1년 뒤 재개 시 v1.1 FINAL의 잠재 결함을 빠르게 회복하기 위해 H1~H8을
한 줄씩 보존:

- **H1**: AI-Safe Rule 1.5 본문 부재 — 정의 누락
- **H2**: Few-shot 4~49개 회색지대 — 토큰/판단 테스트 기준 추가 필요
- **H3**: HyperCLOVA 실측 누락 — [B-6A] 5개 모델로 확대
- **H4**: 외부 API 폴백 사전 계약 공백 — Year 2 Phase 5로 이월 가능
- **H5**: PIPA 동의 철회 시 LoRA 재현성 충돌 — 4단계 대응 + DB 스키마 3건 확장
- **H6**: R2 GGUF 보관 비용 산정 누락 — $0.80/년 확인됨, 보관 정책 정의 필요
- **H7**: Hard Stop #5 "24시간" 계측 포인트 미정 — 3가지 시각 중 가장 빠른 시점
- **H8**: COVEN 검토서 + META 분석 v1.0 원문 레포 부재 — `docs/AI모델적용/inputs/` 저장 필요

## 10. 1년간 변하지 않을 가치 (시간이 흘러도 살아남을 통찰)

본 논의 4라운드를 거치며 도출된, **AI 도입 여부와 무관하게 본 프로젝트가
유지해야 할 핵심 가치**:

1. **Graph RAG는 AI의 약점(환각)을 구조적으로 차단하는 방어선이다.**
   AI 도입 여부와 무관하게, 사용자에게 노출되는 사실 정보는 항상
   Graph RAG의 truth_weight 정렬 결과 또는 Constants DB 직접 조회를
   거친다.

2. **Hexagonal 분리는 AI 도입을 가능하게 하는 사전 조건이다.**
   `formula.service.ts`와 `explanation.service.ts`를 분리해두면, 1년 뒤
   AI를 explanation 경로에만 끼워 넣고 formula는 안전하게 유지 가능.

3. **사용자 피드백 인프라는 "사람이 만든 콘텐츠 품질 측정"으로도 가치
   있다.** AI 학습 데이터 수집 목적이 아니어도, "도움됐어요/신고" 버튼은
   Year 1 콘텐츠 개선 사이클의 핵심 도구.

4. **시험 정답은 AI에게 절대 위임하지 않는다.** 1년 뒤 SLM이 얼마나
   똑똑해지든, 기출 정답 판정 / 산식 계산 / 법조문 인용은 룰 엔진과
   DB 조회로만. Hard Rule 2/5/11은 **영구적**.

5. **"감안하여 개발" ≠ "AI 우선 설계".** 코드는 깔끔한 도메인-인프라
   분리로 작성하면, 1년 뒤 AI를 끼워 넣을 자리가 자연스럽게 보인다.
   **AI를 위해 코드를 비틀지 않는다.**
