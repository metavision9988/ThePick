>
> 1. 별도 LoRA로 SLM을 특화하는 것이 가능한가?
> 2. 어떤 기능을 LoRA로 특화할 수 있는가?
> 3. 학습용 데이터는 어떻게 확보하는가?
> 4. 손해평가사 외 다른 자격증 (전기/화학 등 회로도/구조)에도 어댑팅 가능한가?

> **결론 요약:**
>
> 1. ✅ **2026년 LoRA는 완전 성숙. 무료 Colab + 20분에 가능**
> 2. ✅ **5가지 핵심 LoRA 어댑터 식별. 시험별 어댑터가 핵심 자산**
> 3. ✅ **사용자 데이터 + Graph RAG 자동 생성으로 확보 가능. 단 라벨링 검증 필수**

> **가장 중요한 발견:**

## 1️⃣ Q1: LoRA 특화가 가능한가? — ✅ 2026년에 너무 쉬워졌다

### 1.1 LoRA의 본질 (필수 이해)

**LoRA (Low-Rank Adaptation):**

- 기본 모델(Llama 3.2 3B 등)의 **97% 가중치는 동결**
- 작은 "어댑터 레이어" 만 추가 (총 파라미터의 0.1~1%)
- **풀 파인튜닝의 90~95% 품질을 5% 비용으로 달성**

```
[기존 방식 - Full Fine-tuning]
  Llama 3.2 3B 전체 가중치 수정
  → VRAM 24GB+ 필요
  → 8시간+ 훈련
  → 비용 $50~200

[LoRA / QLoRA 방식]
  기본 모델 Q4 양자화 + 어댑터 레이어만 학습
  → VRAM 8GB (구글 Colab T4 무료 가능)
  → 20분~2시간 훈련
  → 비용 $0 (무료 Colab) ~ $5
```

### 1.2 우리 프로젝트와의 적합성

```
✅ 적합한 이유:
  - 특정 도메인 (자격시험)에 명확한 경계
  - 훈련 데이터를 우리 Graph RAG에서 자동 생성 가능
  - 어댑터별로 분리/교체 가능 (멀티시험 구조와 일치)
  - 수익 증명 후에 시작해도 늦지 않음 (실험 비용 거의 0)

✅ 2026년 표준 도구:
  Unsloth: 2x 빠른 훈련, 70% VRAM 절감
  DoRA (Weight-Decomposed LoRA): 복잡한 도메인에 더 좋음
  Axolotl: YAML 기반 (재현 가능)
  LlamaFactory: Web UI (비개발자도 가능)

✅ 기본 권장 설정 (2026):
  rank (r): 16
  alpha (α): 16
  use_dora: True
  target_modules: 모든 linear (q,k,v,o,gate,up,down)
  learning_rate: 2e-4
  epochs: 1~3 (200개 이하 데이터는 1~2)
```

### 1.3 우리에게 가능한 LoRA 시나리오

```
시나리오 A: 단일 LoRA로 손해평가사 강화
  목표: Llama 3.2 3B를 손해평가사 전문 모델로 변환
  데이터: 1,000~5,000 Q&A 쌍
  비용: 무료 Colab + 1시간
  결과: 일반 Llama 대비 손해평가사 정확도 +20~30%

시나리오 B: 멀티 LoRA (시험별 어댑터)
  목표: 시험별 LoRA 어댑터 분리
  구조:
    base: Llama 3.2 3B (공유)
    adapter-shps.bin: 손해평가사 전용 (50MB)
    adapter-gijgs.bin: 공인중개사 전용 (50MB)
    adapter-jggs.bin: 전기기사 전용 (50MB)
  실행 시: base 로드 + 사용자 시험에 맞는 adapter 동적 로드
  장점: 디스크 효율, 시험 추가 시 어댑터만 추가

시나리오 C: 기능별 LoRA + 시험별 LoRA (조합)
  layer 1: 손해평가사 LoRA
  layer 2: "암기법 생성" 또는 "힌트 생성" 등 기능별
  → 합성 가능 (PEFT 라이브러리 지원)
  → 우리 v3.0의 "Service vs Plugin" 계층과 일치
```

### 1.4 결정적 발견: Phi-4-multimodal의 "Mixture of LoRAs"

Microsoft가 2026년에 발표한 Phi-4-multimodal 모델은 **이미 Mixture-of-LoRAs 아키텍처**입니다:

- 텍스트 base + Vision LoRA + Audio LoRA
- 입력 모달리티에 따라 동적으로 어댑터 선택

**우리 적용:**

- 손해평가사 LoRA + 공인중개사 LoRA + 전기기사 LoRA
- 사용자가 시험 전환하면 어댑터만 교체
- base 모델은 그대로 (메모리 절약)

**이것이 우리 ExamAdapter 패턴의 LoRA 버전입니다. 이미 설계 일치.**

### 2.2 각 LoRA 어댑터 상세 설계

#### LoRA #1: 시험별 도메인 특화 (가장 가치 있음)

```
목적:
  Llama 3.2 3B를 손해평가사 / 공인중개사 / 전기기사 등
  특정 시험의 "전문가"로 변환

데이터 구조 (JSONL ChatML):
  {
    "messages": [
      { "role": "system",
        "content": "당신은 손해평가사 시험 전문가입니다.
                    농어업재해보험법과 산식 계산에 정통합니다." },
      { "role": "user",
        "content": "적과후 착과수조사는 언제 실시하나요?" },
      { "role": "assistant",
        "content": "적과후 착과수조사는 농어업재해보험법 시행령
                    제15조에 따라 적과 종료 직후부터 ... [Graph RAG 결과]" }
    ]
  }

데이터 양: 1,000~5,000 쌍
훈련 시간: T4 GPU 30분~2시간 (Unsloth + QLoRA)
비용: 무료 (Colab)

기대 효과:
  - 일반 Llama 대비 손해평가사 정답률 +25%
  - 한국어 자연스러움 +30% (도메인 어휘 학습)
  - Graph RAG 출력을 더 자연스럽게 표현
```

#### LoRA #2: 암기법 생성기

```
목적:
  주어진 개념에서 "재미있고 외워지는 암기법" 자동 생성
  (현재는 인간이 일일이 만들고 있음)

데이터 구조:
  {
    "messages": [
      { "role": "system",
        "content": "다음 개념의 암기법을 만들어주세요.
                    혼동 유형: numeric_similarity (숫자 혼동)
                    선호 방식: acronym (두문자어)" },
      { "role": "user",
        "content": "보장방식 5종: 적과전, 적과후, 종합위험, 수입감소, 비가림" },
      { "role": "assistant",
        "content": "🎯 **'적적종수비'** 로 외우세요!
                    적(과전), 적(과후), 종(합위험), 수(입감소), 비(가림)

                    💡 연상: 적이 적으로 종수에 비를 뿌린다 → '적의 적이 종(가)의 수에 비를 부어!' " }
    ]
  }

데이터 양: 200~500 쌍 (양질이 중요)
훈련 시간: 20분
비용: 무료

기대 효과:
  - 새 시험 콘텐츠 구축 시 인간 작업 시간 80% 절감
  - 암기법 일관성 향상 (스타일 통일)
  - 우리 독점 자산 (다른 학원이 복제 불가)

⚠️ Hard Rule #14 적용:
  생성된 암기법은 반드시 역방향 검증 통과해야 사용
  (암기법 → 원래 개념 복원 가능한지)
```

#### LoRA #3: 혼동 유형 감지기

```
목적:
  사용자가 오답을 선택했을 때
  어떤 혼동 유형인지 자동 분류

데이터 구조:
  {
    "messages": [
      { "role": "system",
        "content": "사용자의 오답 패턴에서 혼동 유형을 분류하세요.
                    선택지: numeric_similarity, scope_confusion,
                    temporal_confusion, conditional_confusion, ..." },
      { "role": "user",
        "content": "정답: 5%, 사용자 답: 50%" },
      { "role": "assistant",
        "content": "numeric_similarity (95% 확신)
                    이유: 숫자가 10배 차이로 자릿수 혼동 패턴" }
    ]
  }

데이터 양: 500~1,000 쌍
훈련 시간: 30분

기대 효과:
  - 베타 사용자 데이터 축적 후 자동 분석
  - 약점 분석의 정확도 향상
  - 개인화 학습 플랜 강화
```

#### LoRA #4: 50대 친화 해설 톤 변환기

```
목적:
  Graph RAG 해설을 50대 사용자가 이해하기 쉬운 톤으로 변환

데이터 구조:
  {
    "messages": [
      { "role": "system",
        "content": "다음 법령 해설을 50대 수험생이 이해하기 쉽게
                    재작성하세요. 한자어를 풀어쓰고, 일상 비유를 추가합니다." },
      { "role": "user",
        "content": "[원본] 적과후 착과수조사는 적과 종료 직후
                    실시하며, 표본 추출 방식으로 진행한다." },
      { "role": "assistant",
        "content": "[변환] 사과를 솎아낸 직후에 하는 조사예요.
                    농가 전체를 다 세는 게 아니라,
                    몇 그루를 골라서 평균을 내는 방식입니다.

  }

데이터 양: 100~300 쌍 (인간이 직접 작성한 양질)
훈련 시간: 20분

기대 효과:
  - 50대 사용자 만족도 향상

```

#### LoRA #5: 문제 난이도 분류기

```
목적:

### 2.3 LoRA를 만들지 말아야 할 기능

```
❌ 산식 계산
  이유: math.js AST가 100% 정확. LoRA는 환각 가능
  → Hard Rule #2 (LLM 연산 금지) 위반 위험

❌ 법령 조문 인용
  이유: Graph RAG가 직접 조회. LoRA는 환각 가능
  → Hard Rule #5 (Constants 직접 조회) 위반 위험

❌ 기출 정답 판정
  이유: 100% 정답이 절대 기준. LoRA는 99% 수준
  → Hard Rule #11 (기출 정답 최우선) 위반 위험

❌ Ontology ID 생성
  이유: Schema Validator가 절대 기준
  → Hard Rule #8 (Ontology Lock) 위반 위험

원칙:
  LoRA는 "표현/판단/분류"에 사용
  사실 데이터는 항상 Graph RAG / DB / Engine
```

## 3️⃣ Q3: 학습용 데이터는 어떻게 확보하는가?

### 3.1 2026년 LoRA의 핵심 원칙

> **"200개 양질 > 2,000개 자동 생성"**

Unsloth/Axolotl 커뮤니티의 합의: **데이터 품질이 양보다 압도적으로 중요**.

### 3.2 우리 프로젝트의 4가지 데이터 소스

#### Source A: Graph RAG 자동 생성 (대량, 검증 필요)

```
방법:
  Graph 노드 + 기출 문제 + Claude Haiku 조합
  → 자동으로 Q&A 쌍 생성

프로세스:
  1. Knowledge Node 1,140개 중 truth_weight 7+ 추출
  2. 각 노드에 대해:
     - Claude Haiku로 5가지 질문 생성
     - 각 질문에 대해 Graph RAG로 답변 생성
     - 합쳐서 5,700 Q&A 쌍
  3. 인간 검증 (10% 샘플링) → 품질 80% 이상 확인
  4. JSONL 변환

비용: Claude Haiku $5~10
시간: 자동 생성 2시간 + 인간 검증 4시간

장점: 대량 확보 가능
단점: 다양성 부족, 자체 한계 학습 위험
```

#### Source B: 사용자 실제 데이터 (양질, 점진적)

```
방법:
  베타 운영 중 수집한 실제 사용자 질문 + 만족 답변

수집 가능한 데이터:
  - 사용자 자유 질문 (AI 튜터)
  - 사용자가 "도움됐어요" 평가한 답변
  - 사용자 오답 → 우리 해설 → 사용자 "이해됨" 클릭
  - 사용자가 신고한 답변 (반대 학습용)

프로세스:
  베타 3개월 → 1,000~3,000 양질 샘플 확보 가능

장점:
  - 실제 시장 니즈 반영
  - 다양성 자연스럽게 확보
  - 경쟁자 복제 불가능 (우리만의 자산)

단점:
  - 시간이 걸림 (Year 1 후반에야 충분)
  - 개인정보 처리 (PIPA 동의 필수)
  - 라벨링 검증 필요
```

#### Source C: 인간 직접 작성 (소량, 최고 품질)

```
방법:
  진산님 또는 합격자가 직접 작성한 양질 샘플

용도:
  - LoRA #2 암기법 생성기 (200~300개)
  - LoRA #4 50대 친화 톤 변환기 (100~300개)

작성 비용:
  진산님 직접: 50개/시간 → 300개 = 6시간
  외주 (합격자): 1개당 5,000원 × 300 = 150만 원

권고:
  암기법은 진산님 직접 작성 (가장 잘 아심)
  톤 변환은 50대 합격자 외주 (당사자가 가장 잘 앎)
```

#### Source D: 공개 데이터셋 (보조)

```
방법:
