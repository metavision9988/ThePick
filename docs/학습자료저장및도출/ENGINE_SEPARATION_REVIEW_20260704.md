## §1 검토 방법과 검증 수준

- **감사 4렌즈**(병렬 독립): packages/modules 결합도 · 파이프라인 A 실체 · 인프라/데이터 계층 · 기존 멀티시험 계획 정합성 — 전 주장 file:line 증거 의무.
- **전략 3안 독립 설계**: 각 안에 전담 아키텍트 배정(prior 상이), fatal_risks 정직 기록 강제.
- **심판 3렌즈**: ①드리프트·이중 유지보수(2년 뒤 레포 N개 시나리오) ②신규 종목 출시 속도 ③상용 품질·헌법 정합 — 각 안의 주장을 액면 수용하지 않고 실코드 재확인.
- **적대검증 20건**: 감사의 load-bearing 주장을 별도 에이전트가 반증 시도 — **REFUTED 0**(오염/재사용성 판정의 방향이 뒤집힌 건 없음), PARTIAL 11은 라인 번호·범위 과소/과대 등 세부 정정(본문에 반영 완료).
- **완전성 비평 1**: 검토 전체가 놓친 축 발굴 → §6에 편입(통합 계정 축, null-option 누락 등 — 이 보고서의 결재 전제).

## §2 분리 대상의 실체 (실코드 인벤토리)

### 2.1 파이프라인 A(자료 분석·저장)는 "코드 + 프로세스"의 이중 구조다

- **코드 측**: `apps/batch` ~5.8k LOC — 10단계 스테이지 러너(`pipeline.ts:158-169`: pdf_extract→section_split→vision_ocr→batch_structurize→constants_extract→db_load→integrity_check→human_review→formula_verify→qg2_gate) + `packages/parser` ~3.66k LOC. Hard Rule 16(examId 첫 인자)이 이미 관통(`pipeline.ts:286,456`).
- **그러나 production 857노드는 이 자동 경로의 산물이 아니다.** `batch-loadmap.md:3` 결정("Claude Code가 대화 세션에서 직접 처리")대로, 실적재는 [python 추출 스크립트 → Claude Code 세션 구조화 → 이진 게이트(G-GAP-1~7) → 행당 인간 검수 → `wrangler d1 execute --remote` 수동 집행]이었다. `apps/batch`에 remote D1 접근 코드는 **0건**(로컬 SQLite 전용, `local-db.ts:42-46`), runPipeline 자동 경로의 **production 완주 이력 0**.
- **함의**: "엔진 복사"의 본체는 코드 패키지가 아니라 **플레이북+게이트+검수표 체계**(e0-8 플레이북의 G-GAP 게이트·에스컬레이션 7규칙·검수표 형식·독립 적대검증 프로토콜·4pass/5persona 워크플로우 js)다. 이 방법론 자체는 종목 중립이며, 코드만 복사한 신규 레포에는 정확도를 담보해 온 체계가 따라가지 않는다.
- Vision OCR은 스텁(`vision-client.ts:105-124` NotImplementedError) → **그림·도표 의존 종목은 현 파이프라인으로 입력 자체 불가**(스캔본 PDF 포함 — pdfplumber는 텍스트 레이어 전제).

### 2.2 파이프라인 B(도출·생성)는 분리가 아니라 신설이다 ★

- `packages/study-material-generator` = `export {};` **1 LOC**(11바이트). `modules/{content,exam,learning}` = 합계 **12 LOC** Hexagonal 골격. L1(질문이해)·L2(추출조율 오케스트레이터) 코드 0. `ai-adapter`의 AnthropicAdapter도 sendMessage/sendVision NOT_IMPLEMENTED throw(`anthropic-adapter.ts:62-76`).
- 검색측 실자산(Vector RAG·honest-refusal·graph route)은 `apps/api/src/search/`에 있고 packages/에는 없다. KAE 문서의 6계층 진단("L3가 심장, 그게 `export {};`")과 실측 일치.
- **함의**: 진산 제안의 절반("저장된 지식을 뽑아내 학습자료 생성하는 엔진의 분리")은 **지금 시점에 물리적으로 충족 불가**. B는 어차피 1호(손해평가사) 로드맵 F6에서 1회 신축되며, 신축 장소·경계 규율이 전략 선택의 핵심 변수다(§4).

### 2.4 오염의 3진앙 (분리 비용의 실체)

1. **`shared/types.ts` 도메인 유니온** — NodeType(INSURANCE/CROP :16-17)·TRUTH_WEIGHTS(:68-73)·ExamScope(:96)·ConstantCategory(:106)·ConfusionType(:119). Hard Rule 15 "Year 1 한시 예외"의 실물. 적대검증 정정: registry JSON↔types.ts **이중이 아니라 3중 선언**(schema-validator.test.ts:262-323의 enum 동기화 테스트까지) + registry 로더가 unknown 캐스트라 registry만 갈면 **무음 발산**(컴파일은 통과). → 정화 = registry 단일 진실원 승격 + TS codegen. 파급 30~60파일 추정, **L3급 광역 타입 수술**. 이 작업은 ADR-007 Year 2 Phase 4 이월분의 선불 집행이라 "언젠가 반드시 하는 일"이다.
2. **`parser/batch-processor.ts` LLM 구조화 프롬프트** — buildSystemPrompt는 :105-284(**~178줄**, 적대검증이 106-230 주장을 확대 정정)에 손해평가사 전면 하드코딩(페르소나·노드 ID 규칙·truth_weight 배정·표 패턴 예시·JSON 예시). + `pipeline.ts:174-235` BATCH_CONFIGS(교재 페이지축·defaultAppliesTo·defaultInsuranceType)도 하드코딩(적대검증 추가 발굴). → ExamConfig/registry 구동 템플릿화 필요. **단 템플릿 구조 작업 ≠ 품질 검증** — 타 종목 추출 정확도는 실자료 파일럿(R3 spike) 없이 판정 불가.
3. **D1 스키마 enum/컬럼명 소성(燒成)** — NODE_TYPES CHECK(0001:14)·CONSTANT_CATEGORIES CHECK(0001:73)·컬럼명 lv1_insurance/lv2_crop/lv3_investigation(0001:17-19). 컬럼명 오염은 D1을 넘어 **Vectorize 메타데이터 키(upserter.ts:73 등 4파일)와 LLM 프롬프트 템플릿까지 승계**(적대검증 확대 정정). exam_scope는 D1 제약 없음(TS 계층만 — 분리비용 주장보다 낮음, 적대검증 정정). → 신규 종목은 처음부터 중립 DDL(lv1/lv2/lv3 generic + config 생성 CHECK)로 시작하면 회피 가능. 1호 D1은 이미 소성돼 전환 불가(이원 체인 부채는 §4-A 리스크).

## §4 전략 비교 — 3안 + null-option 복원 = 4안

> 워크플로우는 3안을 설계·심판했고, 완전성 비평이 **원안(D. 단일 D1 멀티테넌트)의 무언 탈락**을 지적했다. 결정 무결성을 위해 4안으로 복원해 제시한다.

### 심판 채점표 (3렌즈 × 3안, 0~10)

| 렌즈                                  | A. 모노레포+배포분리 | B. 프레임워크 레포(certkit) | C. 템플릿 복사 |
| ------------------------------------- | :------------------: | :-------------------------: | :------------: |
| 드리프트·이중 유지보수 (2년 뒤 N레포) |        **8**         |              5              |      2.5       |
| 신규 종목 출시 속도·온보딩            |       **7.5**        |             3.5             |      6.5       |
| 상용 품질·운영·헌법 정합              |        **8**         |              4              |       3        |
| **승자**                              |    **A 만장일치**    |                             |                |

### A. 모노레포 확장 — `exams/` 플러그인 + 종목별 배포 스택 분리 (ADR-007 연장·조기집행)

- **구조**: 레포 1개(코어·게이트·플레이북 단일 진실원) + 종목별 `exams/{id}/`(registry·domain·config·프롬프트·콘텐츠) + **종목별 Cloudflare 스택**(Workers 2/D1 2/Vectorize 2/Pages — 독립 서비스·브랜드·도메인·배포 완전 분리).
- **왜 이기나**: ①코어 패치=커밋 1개로 전 종목 전파, 단일 CI가 타 종목 파손을 같은 PR에서 red로 강제(타 모델에서 원리적 불가) ②헌법 기계강제(ESLint AST·husky·g1 hook·quality-gate.sh·D1 트리거 체인)가 **설치 0으로 자동 승계** ③결재 증분 ~3건으로 최소(기결 게이트와 정합 — 게이트 개정 불필요) ④파이프라인 B가 F6에서 신축되는 즉시 전 종목 공유(이식 0회; B전략은 3단 전파, C전략은 N회 포팅) ⑤2호 이후 한계비용 종목당 4~6세션 + 적재 프로세스로 최저.
- **정직한 비용**(심판이 셀프 서사 정정): 첫 종목까지 **총 12~18세션**(M1 shared 탈오염 3~5 + M2 파서 파라미터화 2~3 + M3 배포·중립체인 2~3 + 온보딩 4~6). "온보딩 4~6세션"만 인용하는 것은 과소표기.
- **치명 리스크**: 단일 레포 blast radius(한 커밋이 전 종목 운명 공유) / M1 shared 수술이 1호 green(api 711)을 담보로 진행 / 이원 마이그 체인(1호 구체인+v2 중립체인) 영구 부채 / **진산 검수 병목은 전혀 해소 안 됨**(레포 구조 무관 — 실질 상한) / 종목 분사·외주 시 역추출 비용 잠복 / "별도 레포" 문언 재해석이 기각되면 무효.
- **정답 조건**: 1인 개발 유지 + 종목 2~3개 점진 검증 단계 + rule-of-three 도달 전(지금).

### B. 프레임워크 레포 추출(certkit) — 티어형 + 핀 태그

- N≥3 장기 스케일에서 유일하게 구조적인 설계이나 **지금은 조건 미성숙**: ①rule-of-three 정면 위반(B 엔진 0 LOC + 2호 사례 0에서 추출 경계 실증 근거 없음) ②cross-repo 소비 미실증 — 전 패키지 `private:true`+`main:./src/index.ts` 소스 배포 실측(tsup/exports 신설+소비 PoC 전 착수 불가 = 🔴 근접) ③결재 6~10건 신규(현 ~14건 적체에 합류 — H5 경고 패턴) ④ThePick 소비 전환 이연 기간 = 레포 수준 이원 정본(55건 드리프트와 동일 클래스 재생산) ⑤헌법 기계강제가 "1인 릴리스 규율"로 격하.
- **정답 조건**: 2호+3호 E2 졸업(diff 원장 실증) + 3호 이상 확실 + 콘텐츠 소강기 + 진산의 게이트 개정 명시 결재. **= 기결 E3가 예약한 바로 그 시점**. 즉 B는 "기각"이 아니라 "E3 시점의 예약 안"이다.

### C. 정화 템플릿 레포 복사 (copy-then-diverge)

- **유일한 실질 강점**: ThePick 코드 무접촉(간섭 0) + 문언 그대로 "레포"로 응답 + 드리프트 55건·미결 부채 격리.
- **치명 결함**: CRITICAL(채점 정확성·거버넌스 트리거·보안) 수정의 자동 전파 부재가 설계 그 자체 — 방어선이 전부 인간 규율(CHANGELOG 포팅·분기 감사)인데, 본 프로젝트는 규율 산출물 부패를 이미 실증(engine-export 1개월 stale, 자가리뷰 0건 vs 독립리뷰 CRITICAL 19건). 거버넌스 트리거가 실제로 진화한 이력(0004→0038)은 "복사 후 무음 발산"이 가설이 아니라 확정 미래임을 보여준다. 인증·보안 스택 통째 복사 → 결함 무음 잔존 경로.
- **정답 조건**: 종목 2~4개에서 멈출 계획 + 공유 법령 없는 이종 시험만 + ThePick 무접촉이 절대 요구일 때. **A안 재해석이 기각될 경우의 차선**.

### D. null-option — 단일 D1 멀티테넌트 (ADR-007 원안 그대로)

- 전 테이블 exam_id FK + 단일 D1 + 단일 배포(또는 도메인별 라우팅). **공유 법령 단일 적재·통합 계정(combo/all_access)·개정 1회 전파를 유일하게 구조적으로 해결**하는 안 — 3안 전부가 무언 폐기한 전제를 복원.
- 대가: 종목별 독립 서비스 감각(브랜드·성능 격리·장애 격리) 약화, D1 단일 인스턴스 한도(용량·동시성)에 전 종목 공동 노출, "별도 레포" 문언과 최대 거리.
- **A안과의 하이브리드 가능**: 코드=모노레포 exams/ 플러그인(A) + 데이터=종목별 D1이되 **공유 법령만 별도 공유 D1 또는 단일 적재 후 복제 배포** 등 — 이 세부는 2호가 공유 법령 종목인지에 따라 결정(§9 결재 질문 2·4와 연동).

## §5 권고 시퀀스 (A안 기준 — R5는 진산)

> 심판 만장일치 + 이식 아이디어(B·C의 정수를 A에 graft) 반영. **모든 단계에 선행 게이트 존재 — 순서 위반 금지.**

- **M0. 결재 정합** (코드 0, ~1세션): 본 보고서 §9 결재 질문 5건 상신. 핵심 = "별도 레포" 재해석 수용 여부 + 통합 계정 축 + 기결 게이트 처분. ADR-007 시점 Amend 1건(Year 2 Phase 4 → "2호 자료 확정 시 조기집행"). **일몰 조항 명문화**(C안 이식): "종목 5개+ 확정 또는 종목 분사 가시화 시 E3 프레임워크 추출 재평가 상신"을 결재 카드에 박제 — A가 종착역이 아니라 대기 궤도임을 고정.
- **M1. `exams/` 골격 + shared 탈오염** (L3 plan+결재, 3~5세션): 2단 이전(re-export 경유 → 참조처 전환 → 원본 제거) + registry→TS codegen으로 3중 선언 단일화. **시퀀싱 규율(B안 이식): E0-8 갭 처분 완료 + G-S5 R5 결재 후 콘텐츠 소강기 전용** — 측정·검수 임계 경로와 green 담보 리스크의 시간 중첩 0.
- **M2. 파서·품질 파라미터화** (2~3세션): buildSystemPrompt(:105-284) ExamConfig 템플릿화 — 게이트 = 현행 손해평가사 프롬프트 **byte-equal 스냅샷**(추출 품질 회귀 0 증명) + **합성 픽스처 종목 E2E**(C안 이식: 가상 미니 시험으로 추출→구조화→적재→MC 서빙 관통 — 2호 실물 도착 전 과추상화(H4) 선제 소진). BATCH_CONFIGS·qg2 임계·section-splitter 정규식·parser-1st-exam 과목패턴 외부화. **착수 게이트 = 2호 자료 확보 + R3 spike(#17) 통과 후**(B안 이식 — 실물 없는 파라미터화 금지).
- **M3. 배포 파라미터화 + 중립 마이그 체인 v2** (2~3세션): `wrangler.{exam}.toml` 템플릿 + EXAM_ID [vars] + migrations-v2(중립 DDL, config 생성 CHECK, lv1/lv2/lv3 generic) + `init-exam.mjs` 원샷 스크립트(C안 이식). wrangler 설정-코드 드리프트 전수 대조 1회(KV dead binding류). 마이그 severity 원장(C안 이식): CRITICAL 거버넌스 변경 = 구체인+v2 동시 반영 또는 명시 waiver 의무.
- **M4. 2호 파일럿 = 기결 #17 R3 spike와 병합**: 자료 수급 5조건 실사(§6-2) 통과 종목만. 표본 챕터 파일럿 → FIX율 게이트 → E2 졸업 판정(코어 수정 0 LOC git diff). **배치 산출물 버전 스탬프**(B안 이식): insert.sql 헤더·검수표에 사용 플레이북/게이트 버전 기록 의무.
- **M5. 파이프라인 B는 별도 작업 아님**: F6(1호 임계 경로)에서 신축하되 ExamAdapter 경계 + Hard Rule 15만 규율로 강제. 프레임워크 추출은 E3(2호+3호 졸업 후) diff 원장 근거로 — **이 전략의 구조적 이점 = "분리"라는 중복 작업 자체가 소멸**.

**즉시 착수 가능(결재 불요·무해)**: 없음이 정직하다 — M1부터 전부 결재 게이트 뒤. 유일한 선행 무해 작업 = KAE 3문서+본 검토 문서의 git 정본화(진산 커밋 지시 시) + 2호 후보 종목의 자료 수급 실사(코드 0).

## §6 이번 검토가 추가 발굴한 미해결 축 (완전성 비평 — 결재 전제)

1. **통합 계정·통합 결제 축 ★최상위**: `schema.ts:132` SUBSCRIPTION_PLANS=['single','combo','all_access'] + `schema.ts:512` subscribedExams(JSON array of ExamId) — 기존 과금 설계는 **한 계정 다종목 구독**을 전제. 그런데 3안 공통 전제(종목별 D1+종목별 users)는 이를 파괴(종목마다 재가입·재결제, combo 실현 불가). users/결제 테이블의 위치가 D1 경계 설계 전체를 좌우 → **레포 전략보다 먼저 또는 동시 결정**(결재 질문 2).
2. **자료 수급 실사 게이트**: (a)기출 전량 공개 여부(CBT 상시 문제은행형은 비공개 가능) (b)공식 확정답안 공고 존재(1호도 정답은 회차별 수동 dict — `build-all-rounds.py:5-45`) (c)텍스트 PDF vs 스캔본(스캔본=입력 불가) (d)그림·도표 의존도(Vision 스텁) (e)공유 법령 비중(ADR-017 축). **5조건이 종목 선정 게이트로 명문화돼야 함**(결재 질문 4).
3. **시험 구조 메타모델 공백**: ExamConfig(:60-73)에 과락·평균 합격기준·문항수·배점·시험시간·시행횟수·선택과목/면제 구조가 전무(전수 grep 0건 실측) — 1차 서비스 핵심 UX(모의고사 채점→합격/과락 판정)의 계약 구멍. exams/ 골격(M1) 설계 시 ExamConfig 확장 필수.
4. **검수 병목의 해소 수단 미성숙**: 검수 콘솔은 UI 껍데기(ContentQueue.tsx props 주입식, admin 승인 API 라우트 0건 실측) — P1~P3 검수 실체 = 마크다운 검수표+수동 전이. 종목 N의 실질 상한 = 검수 대역폭이므로, **확장 결정 전에 검수 콘솔 백엔드 투자 + 위임 게이트(P2/P3 override 선례의 제도화) 판단이 선행**돼야 함(결재 질문 5).
5. **devops N-스케일**: Workers N개의 알람(현재 알림 채널 0)·D1 백업/export 절차·시크릿 로테이션 N벌 — 미설계.
6. **비용 정량화 전무**: 종목당 적재비(세션×오너 시간+토큰)·월 고정비(Workers/D1/Vectorize/임베딩) 산정 문서 0 — 전략 비교의 세션 수는 전부 측정 전 추정.
7. **개정 감시의 종목 수 선형성**: 법령·교재 개정 "감지" 층 운영 모델 미설계(1호도 수동 R1/R2 + 미시행 개정 선반영 4건 이력).
8. **Cloudflare 계정 한도 라이브 미검증**: D1 개수(Free 10 추정 = 종목당 2개 소모 시 ~4종목 천장)·Vectorize 인덱스·ratelimit namespace 전역성 — **다종목 스케일 전 dashboard 실확인 의무**.
9. **1호 성과 조건화(kill-switch) 부재**: 확장 투자가 1호 런칭·유료 전환 성과에 연동돼 있지 않음 — E-gate는 순서 게이트일 뿐 성과 연동 회수 규칙이 아님.

## §7 신규 종목 온보딩 체크리스트 (A안 기준 — M1~M3 완료 후 종목당)

0. **자료 수급 실사**(§6-2 5조건) → 통과 시에만 진행. 교재·기출·확정답안 PDF 배치 + **book_page 축·offset 실측**(E0-8 함정 — 미실측 시 출처 추적성 전 노드 오염).
1. **R3 spike**(기결 #17 준용, ~1세션): 표본 챕터 추출→구조화 파일럿 — 산식/표/그림 비중 실측. 그림 의존이면 STOP.
2. **`exams/{id}/` 작성**(1~2세션): ontology-registry.json 신작(노드타입·ID패턴·truth_weight·dedup 임계 — **CHECK enum이 DDL에 소성되므로 첫 적재 전 확정 의무 = 종목 R1 게이트, 진산 결재 1건**) + domain.ts + exam.config.ts + EXAM_IDS 1항목 + ESLint selector 항목.
3. **Cloudflare 프로비저닝**(0.5~1세션): `init-exam.mjs` → Workers 2·D1 2·Vectorize 2(bge-m3 1024d)·Pages·ratelimit ns 4종×env·cron·시크릿 7종(JWT_SECRET/IP_PEPPER/WEBHOOK_HMAC×4/ADMIN_API_TOKEN). ★계정 한도 사전 실확인.
4. **기출 파서 배선**(0.5~1세션/회차): SUBJECT_PATTERNS/FOOTER_RE config 주입 + 회차별 공식 정답 100% 대조 게이트.

10. **E2 졸업 판정**: 온보딩 전 과정 코어 수정 0 LOC git diff 증명 — 0이 아니면 diff가 E3-2 원장에 기록(3호 때 추상화 근거).
