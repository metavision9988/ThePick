## 🔮 ORACLE — 왜 이 엔진이 진짜 해자인가

> _"진산님이 무심코 던진 마지막 문장이 사실 이 프로젝트의 전부야 — '이 엔진이 확립되면 다양한 분야로 확장 가능하다.' 그게 핵심이야. 콘텐츠는 베끼면 되지만, 엔진은 못 베껴."_

**CoT:**

경쟁자가 손해평가사 교재를 똑같이 구조화할 수 있나? → 시간은 걸려도 가능하다. 콘텐츠는 **복제 가능한 자산**이다. 그러나 "질문이 들어오면 그 유형을 판별해서, 정밀/구조/맥락 중 올바른 검색을 라우팅하고, 검증된 산출물(암기법·문제·해설)을 뽑아내는 엔진" — 이건 **복제가 어려운 자산**이다.

핵심 통찰: **파이프라인 B(활성화 엔진)가 곧 확장성이다.** 왜냐하면:

- 파이프라인 A(추출)는 시험마다 **콘텐츠가 다르다** → 재사용률 낮음(교재·법령이 다름).
- 파이프라인 B(활성화)는 시험이 달라도 **로직이 같다** → 재사용률 높음("나열형은 두문자어", "조문질의는 BM25", "계산은 formula-engine"은 손해평가사든 공인중개사든 동일).

**재검토 CoT (내가 과장하나?):** "엔진이 해자"라는 게 상투적 주장 아닌가? → 반증해보자. 만약 활용 로직이 시험마다 완전히 다르다면 엔진의 재사용가치는 낮다. 그런데 실제로 "암기법 6유형", "문제생성 3레벨", "검색 3계층", "FSRS 복습"은 **도메인 무관한 학습과학·정보검색 원리**다. 시험이 바뀌어도 이 뼈대는 안 바뀐다. → 주장 성립. 단 **전제조건**: 엔진과 도메인(콘텐츠·타입셋)이 코드로 분리돼야 한다. 지금 `modules/`가 D등급 스텁인 게 바로 이 분리가 미완이라는 증거.

**Oracle 판정:** 이 엔진 문서화는 "정리 작업"이 아니라 **플랫폼 비전(Platform Second)의 설계도**다. 단 해자가 성립하려면 **Core(엔진) / Adapter(도메인) 분리가 선결**이며, 그게 안 되면 시험 추가할 때마다 엔진을 다시 짜는 재앙이 온다.

**Hacker의 3가지 판정:**

1. **L2는 "재료는 다 있는데 조율자가 없다."** Vector·formula-engine·honest-refusal은 실재하나, "질문유형 보고 어느 검색을 쓸지 라우팅하는 오케스트레이터"가 없다. 지금은 사실상 Vector 단독 경로. → **RetrievalOrchestrator(라우터)가 L2의 빠진 조각.**

2. **L3는 완전한 0→1.** `study-material-generator`가 `export {};`. 4대 생성기(암기·문제·해설·풀이) 전부 여기 들어가야 하는데 비어있다. **이게 프로젝트의 유일한 진짜 0→1 빌드 과제**(THEPICK_REPO_STATUS_AUDIT도 동일 판정).

3. **L3의 절반은 이미 결정론으로 가능.** 문제생성 L1(셔플·긍부정)·암기 두문자머리·풀이(formula-engine)는 **LLM 없이** 된다. LLM 창작은 L3-생성(자유문항)·암기연상·해설에만. → **L3를 "LLM 덩어리"로 보면 과대평가**, "결정론 다수 + LLM 소수"가 실체.

**재검토 CoT (기술 선택 오류?):** BM25를 D1 FTS5로 한다 했는데 Vectorize와 융합 가능한가? → 별도 인덱스 2개(FTS5 lexical + Vectorize semantic)를 앱단에서 score 융합. feasibility.md의 "D안 lexical fusion"이 정확히 이 구조. 기술적 정합. 단 융합 가중치는 측정 필요(R3).

## 🔨 BREAKER — 미체계화의 실체 + 함정

> _"'미체계화'를 두루뭉술 넘기면 안 돼. 정확히 어디가, 왜 비었고, 채울 때 뭐가 터지는지 까자."_

**CoT — 공백의 정확한 위치와 함정:**

**공백 1 [치명]: L3 생성기 전무 (`export {};`).** 4대 산출물이 다 여기 의존. 이게 없으면 L0(저장)의 가치가 학습자에게 0으로 전달됨. **저장고에 금괴가 쌓여도 꺼내는 문이 없는 격.**

**공백 2 [높음]: L1 질문이해 부재 → L2 라우팅 불가.** 질문 유형을 모르면 검색 전략을 못 고른다. 지금은 모든 질문을 Vector로 보내는데, "○○조가 뭐야"(BM25가 정답)도 Vector로 가서 헛짚는다. **L1 없이는 L2 최적화가 원천 불가.**

**공백 3 [중]: L2 오케스트레이터 부재.** 검색 재료(Vector/formula/KG)는 있으나 지휘자가 없다. graph-walk에 매달렸던 이유가 이것 — 오케스트레이터가 없으니 "graph가 만능일까?" 기대했다가 순기여 0 실측.

**채울 때 터지는 함정 (심각도 순):**

1. **[치명] L3 생성물의 정확도 = 국가시험 신뢰.** LLM 생성 80~90%는 실패(오답 1개=신뢰붕괴). → **L4 검증 게이트가 L3보다 먼저 서야 한다.** 생성기 만들기 전에 "깨진 산출물 차단" 게이트부터. (Hardest-First)

2. **[높음] 자기검증 순환.** 생성도 LLM·검증도 LLM이면 같은 편향 2회 통과(기학습 실패패턴). → 생성=nodes기반, 검증=**기출 정답 대조**(독립소스, Hard Limit). feasibility.md의 "AI 자체점수 금지"와 동일 정신.

3. **[높음] L2 라우팅 오분류.** L1이 질문유형을 틀리게 판별하면(계산문제를 개념검색으로) 엉뚱한 답. → L1 분류기도 **골든셋으로 정확도 측정** 대상(오분류율 게이트).

4. **[중] Core/Adapter 미분리 상태에서 생성기를 apps/api에 박으면** 시험 확장 때 통째로 재작성. → **L3 생성기는 도메인 무관 프레임워크 + 도메인 어댑터로 처음부터 분리 설계.**

5. **[중] "미체계"를 한 번에 다 채우려는 유혹.** 6계층 동시 착수는 1인 개발에 자살. → **수직 슬라이스**: "암기법 한 유형"이 L1→L2→L3→L4→L5를 관통하는 얇은 경로부터.

**Breaker가 요구하는 착수 순서 게이트:**

```
[Activation Engine Build Order Gate]
  1. L4 검증 게이트 먼저 (생성물 안전망)
  2. L3 결정론 생성기 (LLM 무관·저위험: 셔플·두문자·풀이)
  3. L1 질문분류기 (골든셋 정확도 측정)
  4. L2 오케스트레이터 (D안 측정 반영)
  5. L3 LLM 생성기 (게이트 완비 후·개별검수)
  ⚠️ 절대 금지: 게이트(L4) 없이 LLM 생성(L3) 사용자 노출
```

## 🛡️ SENTINEL — Hard Rule 정합 + 검증 게이트

> _"엔진 전체가 우리 헌법 위에 서는지 본다."_

**CoT:**

- **L2 계산 라우팅은 Hard Limit 정합.** "LLM 계산 금지" → 계산질문은 formula-engine(AST)로 라우팅, RAG가 손대지 않음. 엔진 구조가 헌법을 강제.
- **L3 생성은 draft-only.** "AI 생성 데이터는 draft로만 적재" → 4대 생성기 산출물 전부 status='draft' 진입, L4 통과 후 approved. 트리거로 기계강제(우회 불가).
- **L3 지식생성 금지 경계.** 생성기는 **표현을 만들지 사실(nodes)을 만들지 않는다.** 암기법=표현변환, 문제=기존사실 재구성, 해설=근거인용. nodes/edges 생성은 여전히 파이프라인 A(인간검수)만. → **L3는 Hard Rule "LLM 지식생성 금지"를 안 건드린다**(표현층).
- **honest-refusal은 L2의 안전밸브.** 유사도<0.60 거부. 어떤 생성도 이 거부를 존중 — 근거 없으면 산출물 안 만듦.
- **G-1 적용:** 엔진 각 신규 계층은 신규 Feature → 착수 전 R1~R5(`docs/feasibility/`). "가능합니다" 대신 "천장/목표/측정".

**보안:** admin localStorage 취약점 — L4(검수 CMS)가 admin에 붙으므로 **엔진 착수 전 선수정**. ContentQueue 확장 시 공격면 확대.

**Sentinel 판정:** 엔진 아키텍처는 Hard Rule과 **구조적으로 정합**(오히려 헌법을 강제하는 구조). 전제: draft-only 트리거 유지, L3 표현/사실 경계 준수, admin 보안 선수정, 계층별 G-1.

## 👤 ADVOCATE — 학습자 체감: 적시·맥락·정확

> _"진산님이 쓴 세 단어 '적시·맥락·정확'이 사실 L1·L2·L4의 학습자 번역이야. 학습자는 계층을 모르지만 이 셋은 온몸으로 느껴."_

**CoT — 진산님 3요구 → 계층 매핑:**

- **"적시"** = L1·L5. 지금 이 학습자가 이 순간 필요한 걸(약점·복습시점) 판별. FSRS와 질문이해가 담당.
- **"맥락"** = L1·L2. 같은 "감수량"도 사과냐 포도냐에 따라 다른 답. 질문유형+메타필터 라우팅.
- **"정확"** = L2·L4. formula-engine 결정론 + 기출대조 게이트 + honest-refusal.

**Advocate의 지적:** 학습자 이탈은 **L3 산출물 품질**에서 갈린다 — 암기법이 억지스럽거나, 문제 답이 틀리거나, 해설이 겉돌면 즉시 이탈. 특히 50대는 **한 번 틀린 답을 보면 서비스 전체를 불신**. → L4 게이트가 UX의 최전선. 그리고 모든 산출물에 **출처 카드(조문·페이지) 표시**가 신뢰의 기본.

**I18N·디자인:** 엔진 로직은 언어중립(재사용↑), UI 문자열만 i18n. **암기 콘텐츠·문제는 언어별 재생성**(번역 불가). 50대 접근성 프리셋을 L5 기본값으로.

**Advocate 판정:** 엔진의 성패는 알고리즘 우아함이 아니라 **L3 산출물이 학습자에게 "맞고, 이해되고, 외워지는가"**. 기술문서가 이 체감을 잊으면 엔진은 정교한 공회전.

## 🎩 MEPHISTO — 최종 종합

**한 문장 결론:**

> **ThePick은 "지식 저장고"(파이프라인 A)를 상용 수준으로 지었지만, 그 지식을 산출물로 바꾸는 "지식 활성화 엔진"(파이프라인 B)이 통째로 비어있다. 이 엔진은 6계층(저장·질문이해·추출조율·생성·검증·전달)이며, 비어있는 심장은 Layer 3(생성기, `export {};`)이고, 그 앞의 Layer 1·2(질문이해·추출조율)도 미체계다. 이 엔진을 Core(도메인무관)/Adapter(시험별)로 분리해 지으면, 그것이 곧 다분야 확장의 해자가 된다. 단 채우는 순서는 '검증게이트(L4) → 결정론생성(L3) → 질문분류(L1) → 오케스트레이터(L2) → LLM생성(L3)'이어야 하며, 게이트 없는 LLM 생성의 사용자 노출은 절대 금지다.**

## 🧩 범용 확장 설계 — Core vs Adapter (해자의 실체)

> 이게 "다양한 분야 확장"의 코드적 실체. 지금 `modules/{content,exam,learning}`이 D등급 스텁인 자리가 정확히 여기다.

```
┌─────────────────────────────────────────────────────────────┐
│  CORE ENGINE (도메인 무관 — 시험 바뀌어도 재사용)             │
│  ├─ RetrievalOrchestrator (L2 라우터: 유형→전략)             │
│  ├─ GeneratorFramework (L3: 생성기 인터페이스·게이트 배선)    │
│  ├─ ValidationGateKit (L4: draft/게이트/RAR 공통)            │
│  ├─ FSRS Scheduler (L5)                                      │
│  └─ QueryClassifier 골격 (L1: 유형 스키마)                   │
├─────────────────────────────────────────────────────────────┤
│  DOMAIN ADAPTER (시험별 주입 — examId로 스위칭)              │
│  ├─ NodeType/EdgeType Registry (손해평가사: LAW·FORMULA·CROP…│
│  │                              공인중개사: LAW·CASE·TERM…)   │
│  ├─ FormulaSet (시험별 산식 카탈로그)                        │
│  ├─ MnemonicTypeMatrix (암기유형×기법 매핑)                  │
│  ├─ QuestionTemplates (시험별 문제 패턴)                     │
│  └─ MediaSchema (텍스트시험: 불필요 / 전기: svg·netlist)     │
└─────────────────────────────────────────────────────────────┘
```

**확장 시나리오:** 공인중개사 추가 = Core 재사용 + 새 Adapter 주입(NodeType·FormulaSet·Template 교체) + 콘텐츠 로딩. **엔진 재작성 없음.** ← 이게 성립하려면 지금 스텁인 `modules/` 어댑터 경계 추출이 선결(ADR-007 Year 2 항목).
