## 🔮 ORACLE — 첨부의 프레임을 어떻게 볼 것인가

> _"첨부를 쓴 사람은 똑똑해. 근데 '일반적으로 좋은 아키텍처'와 '이 도메인에서 옳은 아키텍처'는 달라. 국가시험은 정상적인 소프트웨어 상식이 배신하는 곳이거든."_

**CoT:**

일반 SaaS에서 아키텍트의 본능은 "**처리량 최적화**"다 — 병목 제거, 자동화 격상, 임계치 완화로 응답률 향상. 첨부의 세 처방(Implementation Lock, 0.60 캘리브레이션, RAR 이원화)은 전부 이 본능에서 나왔고, **일반 SaaS라면 다 옳다.**

그런데 이 도메인의 목적함수는 처리량이 아니라 **"틀리지 않음"**이다(exam_ai_finetuning_vs_rag: _"RAG는 똑똑해 보이려 하지 않고 틀리지 않으려 한다"_). 여기서 상식이 뒤집힌다:

- 일반 SaaS: 거부(False Negative)는 나쁨 → 임계치 완화가 미덕.
- 국가시험: **거부는 안전, 오답은 사망** → 임계치 완화가 독.

**재검토 CoT (내가 첨부를 부당하게 깎나?):** 첨부의 처방이 정말 다 틀렸나? → 아니다. **진단은 대부분 정확**하다(Layer 3 갭, RAR 병목은 실재). 틀린 건 **처방의 방향과 강도**다. 그러니 "첨부가 틀렸다"가 아니라 "**첨부의 진단은 수용, 처방은 도메인에 맞게 재보정**"이 정직한 판정이다.

**Oracle 판정:** 첨부는 **"일반 아키텍처 렌즈"**로 정확한 문제를 봤으나, **"국가시험 도메인 렌즈"**로 보면 처방이 3곳에서 반전된다. 메타-리뷰의 임무는 진단을 살리고 처방을 정박시키는 것.

## 🏗️ ARCHITECT — 주장 ① 검증 (SPOF 용어 + Implementation Lock)

> _"첨부가 날 정확히 짚은 부분부터 인정하자 — Layer 3가 핵심 갭이라는 진단은 내 문서와 100% 일치해. 근데 두 가지가 어긋나."_

**CoT — 주장 ① 해부:**

**인정할 부분:** "Layer 2에서 정밀 컨텍스트를 추출해도 규격화된 산출물로 변환하는 엔진이 비어있다" → **정확하다.** 내 엔진 문서의 "L3가 심장, 그게 `export {};`"와 동일 진단. 첨부의 진단력은 인정.

**어긋남 1 [용어] — "SPOF"는 부정확하다.**
SPOF(Single Point of Failure)는 *"존재하는데 죽으면 전체가 멈추는 것"*이다. Layer 3는 **아직 존재하지 않는 미구현 기능**이다. 이건 SPOF가 아니라 **"미완성 핵심 경로(missing critical path)"**다. 사소해 보이나 중요하다 — SPOF 처방(이중화·failover)과 미구현 처방(구현·검증)은 완전히 다르다. 첨부가 SPOF라 부르며 "Implementation Lock(차단)"을 제안한 게 이 혼동에서 나왔다.

**어긋남 2 [처방] — "Implementation Lock(전체 차단)"은 과잉이다.**
근거: 실측상 **Layer 5(학습자 앱)가 이미 부분 작동**한다(MC·FillBlank·StudyFlow). 기출문제 기반 학습은 **Layer 3 생성 없이도** 돌아간다(기출은 이미 approved 콘텐츠). 즉 "생성기 없으면 서비스 전체 정지"가 아니다. 전면 Lock은 **이미 작동하는 기출 학습까지 죽이는** 과잉 처방.

**그럼 첨부의 "단순 템플릿 매핑 엔진" 제안은?** → **방향은 맞고, 이미 프로젝트에 설계돼 있다.** GRAPH_RAG_PIPELINE_MASTER_PLAN의 `study-material-generator` 명세에 이미 `flowchart-generator`·`formula-card-generator`·`flashcard-generator` 등 **템플릿 기반 결정론 생성기**가 그려져 있다(구현만 안 됨). 첨부는 이걸 몰라서 "새 제안"으로 냈지만, 실은 **내가 이미 K1(결정론 생성기 먼저)로 로드맵에 넣은 것**과 수렴한다.

**재검토 CoT (내가 방어적인가?):** "이미 있다"고 깎아내리는 게 자기방어 아닌가? → 점검. 첨부의 기여는 "입출력 형태를 Hard Limit으로 강제하라"는 **강조점**이다. 이건 유용하다 — 생성기가 자유형식이 아니라 **규격 스키마(mnemonic_cards 컬럼 등)로 출력을 강제**하면 L4 검수 부하가 준다. 이 강조는 수용. 단 "전체 Lock"은 반려.

**Architect 판정:** 주장 ① = **진단 수용(Layer 3 핵심갭 정확), 용어 교정(SPOF→미구현 경로), 처방 교정(전체 Lock 반려 → 결정론 생성기 우선 + 출력 스키마 강제).** 첨부의 "출력 형태 강제" 강조점은 흡수.

## 💻 HACKER — 세 주장의 기술적 타당성 개별 채점

> _"논쟁은 코드로. 각 처방이 실제로 구현 가능하고 이 스택에서 말이 되는지 본다."_

**CoT — 처방별 기술 검증:**

| 첨부 처방                     | 기술적 타당성 |             ThePick 스택 정합             |        판정        |
| ----------------------------- | :-----------: | :---------------------------------------: | :----------------: |
| Implementation Lock           | 가능하나 과잉 |    Layer 5 기출학습 이미 동작 → 불필요    |      🔴 반려       |
| 템플릿 매핑 엔진              |     타당      | study-material-generator 명세에 이미 존재 | 🟢 수용(기존 계획) |
| 출력형태 Hard Limit 강제      |   타당·유용   |   mnemonic_cards 등 스키마로 강제 가능    |      🟢 수용       |
| 0.60 A/B 캘리브레이션         |   기술 가능   |     단 방향 재보정 필요(아래 Breaker)     |     🟡 조건부      |
| 기출대조 자동 단위테스트 격상 | **타당·우수** |     기출 정답은 결정론 → 자동화 적합      |      🟢 수용       |
| RAR Fast/Deep 이원화          |     타당      |    단 Hard Rule 7 경계(아래 Sentinel)     |     🟡 조건부      |

**Hacker의 핵심 지적 2가지:**

1. **"기출대조 자동 단위테스트 격상"은 첨부에서 가장 우수한 처방이다.** 기출 정답은 DB에 결정론적으로 존재하므로, "생성 문제의 답 ≟ 기출 정답"은 **완전 자동 검증 가능**(Hard Rule 위반 아님 — 이건 승격이 아니라 _차단_ 게이트). M13(기출 정답 대조기)이 이미 설계돼 있어 **바로 CI에 걸 수 있다.** 이건 흡수 1순위.

2. **단, "자동 단위테스트 통과 = approved"로 착각하면 안 된다.** 자동 대조는 _"틀린 걸 걸러내는"_ 필터지, _"맞다고 승인하는"_ 도장이 아니다. 정답이 일치해도 "오답 선지가 실은 정답일 여지", "암기법이 억지"는 코드가 못 잡는다. → 자동 게이트는 **draft를 걸러낼 뿐, approved 승격은 별개**(Sentinel 영역).

**재검토 CoT (기술 오판?):** 0.60을 "기술 가능"이라 했는데 실제 A/B 인프라가 있나? → 실측상 telemetry·engine-telemetry 테이블은 있으나 A/B 프레임워크는 미확인. A/B보다 **골든 N≥30 확대(feasibility E0-4)로 임계치 검증**이 더 싸고 정확. A/B는 사용자 규모 확보 후. → 첨부의 "A/B" 수단은 시기상조, "캘리브레이션 필요"만 수용.

## 🔨 BREAKER — 첨부가 놓친 것 (핵심 반박)

> _"첨부의 진단은 날카로워. 근데 이 도메인·이 헌법을 모르면 처방이 독이 돼. 첨부가 못 본 세 개의 지뢰를 깐다."_

**CoT — 첨부가 놓친 지뢰:**

**지뢰 ① [치명] 주장 ②의 도메인 비대칭 무시.**
첨부: _"0.60이 False Negative(답변 가능한데 거부)를 얼마나 유발하는지 A/B로 캘리브레이션."_ — 이 문장의 **숨은 전제**는 "거부는 손실"이다. 일반 SaaS엔 맞다. **국가시험엔 치명적으로 틀렸다.**

- False Negative(거부): "이 부분은 교재 O장을 보세요" → 학습자 약간 불편, **신뢰 유지**.
- False Positive(오답): "정답은 3번" (실제 2번) → **신뢰 즉사**(exam_ai_finetuning의 "정답 3번이라며?" 시나리오).
- 두 오류의 비용이 **비대칭**(오답 ≫ 거부)이므로, 캘리브레이션 방향은 "0.60 완화(답변률↑)"가 아니라 **"유지 또는 상향(오답률↓)"**이어야 한다. 첨부는 이 비대칭을 안 짚어서, 처방이 "완화 지향"으로 읽힌다. → **방향 반박.**

**지뢰 ② [치명] 주장 ③의 Hard Rule 7 충돌.**
첨부: _"결정론적으로 판별 불가능한 영역에 한해서만 인간 RAR 개입."_ — 뒤집으면 **"결정론 판별 가능 영역은 인간 없이 approved"**. 이건 Hard Rule 7(_"AI 생성 데이터는 draft로만 적재, 인간 확인 후 approved"_)과 **정면 충돌**한다.

- 정확한 경계(Sentinel 상술): 자동 게이트는 **draft를 걸러낼(차단)** 뿐, **approved 승격은 인간**. 첨부처럼 "인간 완전 배제"로 가면 헌법 위반.
- 단 **강도 조절은 가능**: 결정론 생성분은 자동 게이트 + **샘플 감사**(전수 아닌 표본 인간검토), LLM 창작분은 개별 전수 검수. 이게 Hard Rule을 지키며 병목을 푸는 유일한 경로. → **방향 수용, 헌법 경계 필수.**

**지뢰 ③ [높음] "SPOF" 오진에서 파생된 Lock 과잉.** (Architect 상술) 미구현을 SPOF로 오진 → 전체 차단 처방. 이미 작동하는 기출학습(Layer 5)까지 죽이는 과잉.

**Breaker의 재검토 CoT (내가 첨부를 과하게 때리나?):** 세 지뢰가 첨부를 전면 부정하나? → **아니다.** 지뢰 ①은 "방향만" 반박(캘리브레이션 필요는 인정), ②는 "경계만" 요구(이원화 방향은 인정), ③은 "강도만" 반려(템플릿 제안은 인정). **첨부의 뼈대(진단)는 살고, 처방의 방향·강도·경계만 교정**된다. 이게 공정한 판정.

**Breaker 종합:** 첨부의 세 처방은 **"일반 SaaS 정답"**이나, 국가시험에선 **① 방향(거부는 안전) ② 경계(인간검수 불가침) ③ 강도(전체 Lock 과잉)** 세 축에서 재보정 필수. 진단은 감사히 흡수, 처방은 헌법에 정박.

## 🛡️ SENTINEL — 주장 ③의 Hard Rule 7 정밀 진단

> _"첨부의 RAR 이원화가 우리 헌법 7조를 어디서 넘는지, 밀리미터 단위로 긋는다."_

**CoT — Hard Rule 7 경계선:**

Hard Rule 7 원문(ADMIN_ARCHITECTURE_SUPPLEMENT + GRAPH_RAG_PIPELINE): _"AI가 생성한 모든 데이터는 draft 상태로만 DB에 적재. approved 상태는 인간이 확인 후에만 전환."_

**허용되는 이원화 (헌법 준수):**

```
[자동 게이트 = draft 필터링] — 인간 전(前) 단계, 헌법 무관
  · 기출 정답 대조(M13): 답 불일치 → draft 자동 격리/반려
  · Mnemonic Gate: 두문자 글자수≠항목수 → 자동 폐기
  · Solver Gate: 특이행렬·발산 → 자동 폐기
  → 이 필터는 "틀린 걸 거르는" 것이므로 인간검수를 대체하지 않음. 오히려 검수 부하를 줄임.

[차등 검수 = approved 승격] — 인간 개입, 강도만 조절
  · is_deterministic=1 (셔플·두문자·계산): 자동 게이트 통과분 → 샘플 감사(표본 인간검토) → approved
  · is_deterministic=0 (연상·해설·자유문항): 개별 전수 인간검수 → approved
```

**금지되는 이원화 (헌법 위반):**

```
❌ "결정론 판별 가능 → 인간 0명 → 자동 approved"
   = Hard Rule 7 위반. 어떤 AI 생성분도 인간 확인(최소 샘플) 없이 approved 금지.
```

**핵심 구분:** 첨부의 "Fast-Track"이 **"인간 완전 배제"**를 뜻하면 위반, **"인간 최소화(샘플 감사)"**를 뜻하면 허용. 첨부 문장은 전자로 읽히므로 **명시적 교정 필요.**

**Sentinel의 추가 지적:** 첨부가 "기출 정답 대조를 자동 단위테스트로 격상"한 건 **오히려 헌법 강화**다 — 자동 차단 게이트가 촘촘해지면 인간에게 가는 draft가 이미 정제돼, 인간은 "정답 검증"이 아니라 "교육 적절성"에만 집중. 이건 흡수.

**보안:** RAR 이원화로 ContentQueue를 확장하면 admin 공격면 증가. **admin localStorage 취약점(telemetry 토큰) 선수정** 후 이원화 착수.

**Sentinel 판정:** 이원화는 **"자동=차단 필터 / 인간=승격 게이트(강도 차등)"** 구조로만 허용. "인간 배제"는 Hard Rule 7 위반. is_deterministic 플래그 기반 차등을 ADR로 명문화.

## 👤 ADVOCATE — 학습자 관점에서 세 처방의 실익

> _"학습자는 아키텍처 논쟁 몰라. 근데 이 세 처방이 실제로 학습자한테 뭘 하는지가 진짜 채점표야."_

**CoT — 처방 → 학습자 체감:**

- **주장 ① (Lock):** 전체 차단 시 학습자는 "서비스 준비 중" → **이탈**. 반면 결정론 생성 우선은 "기출+암기 먼저 제공" → 점진적 가치. → **Lock 반대, 점진 찬성.**
- **주장 ② (0.60 완화):** 완화로 답변률↑ 시 학습자는 더 많은 답을 받지만 **틀린 답 섞임** → 50대는 한 번 틀리면 전체 불신. → **완화 반대.** 거부는 "교재 O장 참고"로 안내하면 오히려 **정직한 서비스**로 신뢰.
- **주장 ③ (이원화):** 병목 해소로 신선한 문제 공급↑ → **학습자 이득.** 단 Fast-Track이 품질 훼손하면 역효과. → **이원화 찬성, 품질 게이트 유지 조건.**

**Advocate의 지적:** 세 처방 중 학습자에게 실익이 큰 건 **③(이원화)**이다 — FSRS가 복습 문제를 대량 요구하는데 인간 검수가 못 따라가면 "복습할 문제 없음"이 된다. 단 **출처 카드 표시**(조문·페이지)는 어떤 처방에도 유지 — 그게 거부(②)를 "불친절"이 아니라 "정직"으로 만든다.

**I18N·디자인:** 이원화 UI(ContentQueue Fast/Deep 탭)도 admin 문자열 i18n 셸. 학습자 대면 거부 메시지는 50대 친화 문구("이 부분은 교재 O장을 보시면 정확해요").

**Advocate 판정:** 학습자 실익 순 = **③ 이원화(품질 조건) > ① 결정론 점진 > ② 거부 유지**. ②의 "완화"는 학습자 신뢰를 깎으므로 반대.
