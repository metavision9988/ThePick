# 학습자 노출 문자열의 **빌드 메타 주석** 인벤토리 (2026-08-10)

> 발단: STAGE 2 검수 중 LAW-195 의 3-2 판정이 `0` 이라는 값을 문제 삼았는데, 그 `0` 의 출처가
> description 말미의 **적재 파이프라인 메모** `(수치상수 = ESCALATE, constants INSERT 0.)` 였다.
> 검증 과탐 자체는 사소하나, **학습자에게 보이는 문자열에 빌드 메모가 들어 있다**는 것이 본체다.
>
> 스캔 대상: `docs/batch-load/**/*.sql` 36개 파일의 `knowledge_nodes` INSERT description.
> 결정론 정규식 · LLM 0 · production 무접촉(로컬 SQL 읽기만).

## 요약

| 유형                   | 건수 | 왜 문제인가                                                     |
| ---------------------- | ---: | --------------------------------------------------------------- |
| 배치 식별자(`BATCH-N`) |   21 | 학습자에게 `BATCH-5 영역` 은 아무 의미가 없다. 내부 적재 단위다 |
| ESCALATE 규칙 메모     |    4 | 적재 시 판단 보류 표시. 카드 내용이 아니라 **작업 상태**다      |

**총 25건.** 전부 `description` 본문 안이며, 별도 메모 필드가 아니다.

## ★처분 경로 (중요 — 단순 수정 불가)

CLAUDE.md Hard Limit: **`knowledge_nodes` UPDATE 금지** (개정 시 신규 노드 + SUPERSEDES 엣지).
즉 이 25건은 `UPDATE description` 으로 못 고친다. 가능한 경로는 셋이고 성격이 다르다:

| 안                       | 방법                     | 비용 | 판단                                               |
| ------------------------ | ------------------------ | ---- | -------------------------------------------------- |
| (a) 그대로 둔다          | 없음                     | 0    | 학습자가 `BATCH-5 영역` 을 계속 본다               |
| (b) 표시 계층에서 가린다 | 렌더링 시 메모 패턴 제거 | 소   | **권고** — 데이터 불변 + 즉효. 단 원본은 오염 유지 |
| (c) SUPERSEDES 재적재    | 신규 노드 25 + 엣지 25   | 대   | 이력이 정본. 개정과 같은 절차라 검수 동반          |

**권고 = (b) 먼저, (c) 는 다음 개정 사이클에 묶어서.** (b) 는 되돌릴 수 있고 (c) 는 못 되돌린다.
⚠️ (b) 를 하더라도 **신규 적재분에는 애초에 안 들어가게** 하는 것이 진짜 수리다 —
적재 계약(draft-loader)에 description 메타 주석 금지 게이트를 추가하는 쪽이 근본이다.
