### D-1~D-3 종합 — 메타 교훈

```
메타 검토자는 "독립 컨텍스트"의 검증자였지만,
컨텍스트가 다르다는 것은 곧 "접근 가능한 정보가 다르다"는 뜻.

따라서:
1. 독립 검증자라고 무조건 정확하지 않다 ─ 컨텍스트 격차로 잘못된 의심 발생 가능
2. "이 인용 못 찾겠다"는 의심은 "인용이 잘못됐다"의 증거가 아니라
   "검증자가 못 찾았다"의 증거일 뿐
3. 본 1차 보고서가 부록에서 권고한 "독립 검증" 권고 자체에
   "검증자의 컨텍스트 한계 사전 합의" 항목을 추가해야 함

→ 본 메타-메타 분석을 통해 1차 보고서의 "독립 검증 프로토콜"이
   진화함. 이게 진짜 Compound Engineering의 한 사이클.
```

진산님 의사결정 부담 차원: D-1~D-3에 대해 **추가 액션 불필요**. 본 보고서로 사실 정정 완료.

## Part 3. 부분 동의 (C-1~C-7) 단서들에 대한 응답

### C-1. ADVOCATE 사각지대 — Claude 동의 + 추가 단서

메타 검토자가 단 단서: _"북극성을 '생성물 신뢰성·정확성'으로 명시. 데이터 정확도 우선이 의도된 시퀀싱일 수 있음."_

**Claude 추가 의견**:
이 단서는 정당하지만, "북극성 = 데이터 정확도"와 "베타 출시 시점에 학습자 UX 검증"은 직교(orthogonal)합니다. 데이터 정확도를 우선해도, **검증 시점에 학습자 화면이 없으면 데이터 정확도를 학습자가 인지할 방법이 없음**. 따라서 ADVOCATE 권고(BATCH-1 후 즉시 수직 절단)는 북극성과 충돌하지 않음.

### C-2. ORACLE 출시 데드라인 — ⭐ 가장 중요한 단서

메타 검토자: _"메모리/CLAUDE.md/재정립서 어디에도 '2026년 8월 출시'는 명시 없음. ORACLE이 자체 추정한 가정."_

**Claude 평가**: **메타 검토자의 가장 정확한 지적**입니다.

본 1차 보고서 ORACLE 섹션에서 "현재 4월 25일, 출시까지 6주 남음. 그런데 BATCH 적재만 7주 잡혀있음"이라고 단정적으로 썼는데, 이는 추정에 기반한 것입니다.

**솔직한 정정**:

- 손해평가사 시험은 매년 8월(객관식 1차) — 이건 사실
- 그러나 진산님이 "2026년 8월 시험을 목표로 한다"고 명시하신 메모리/문서는 **없음**
- ORACLE의 결론(MVP-α 전환)은 "2026 8월 목표"라는 가정 위에서만 강력 권고
- 만약 "2027 8월" 또는 "시기 미정" 또는 "Year 1은 데이터/Year 2는 학습자"가 의도라면 → 현 plan 직진이 정합

### C-6. SENTINEL D1 binding 분리 — 메타 검토자가 잘못 짚었을 가능성

메타 검토자: _"Cloudflare D1은 단일 인스턴스에 multi-binding 불가 (현재 시점 SDK 한계). D1 분리 = 비용 2배."_

**Claude 검증 필요**: 이 주장이 사실인지 확인이 필요합니다. Cloudflare D1은 **단일 인스턴스에 multi-binding은 가능**(다른 worker에서 같은 D1 binding) — 다만 binding 단위 권한 분리(read-only vs write)는 SDK 차원에서 어려운 게 사실. 메타 검토자가 binding과 권한을 혼동했을 가능성.

**정확한 권고로 정정**:

```
D1 권한 분리는 다음 두 가지 차원으로 분리:
1. binding 분리 (가능): batch worker / api worker 각각 D1 binding 등록
   → 단일 D1 인스턴스를 두 worker가 공유, binding은 별개
   → 비용 추가 X
2. 권한 분리 (현재 SDK 한계): binding 자체에 read-only 옵션 없음
   → 코드 차원 (예: knowledge-* 테이블만 write 함수 노출) 또는
     별도 D1 인스턴스 (이게 비용 2배) 중 선택

추천: 1번(binding 분리) 즉시 도입, 2번은 Phase 1 후반에 검토
→ 메타 검토자 권고(D1 분리 = 비용 2배)는 옵션의 일부만 본 것
```

```

  ✓ 독립 검증의 가치: X-1/X-2/X-4 같은 새 위험 발견

  - "인용 사실성은 검증 범위 외" 명시
  - "추가 발견 / 위험 평가 / 권고 합리성"만 검증 요청
```
