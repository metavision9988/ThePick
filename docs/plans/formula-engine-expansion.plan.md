## §0 목적·범위

### 0.1 목적

전기기사(2호) 수치 공식 표현률을 현행 47%(게이트 70% 미달)에서 88%(표본값)로 회수하는 최소 확장. S6 §5 권고 "Tier 1+2 = 표적 L3 plan 1건" 이행.

### 0.2 범위

- **In (Tier 1)**: π·e **상수 공급** — 주입 경로 자체가 Q1 결재 대상(rev2 정합화: 종전 "constants DB 적재(코드 0)" 문구는 §3-1 권고 (iii) 엔진 내장과 상호모순이었음). **권고 = 엔진 내장(piDependencies/eDependencies) + constants DB 미적재** — 수학 보편 상수의 정본은 math.js 내장값이며 DB 병행 적재 = 이중 진실원(65↔60 검증 클래스는 교재 유래 상수에 적용되는 규율 — π는 해당 없음). 검증 = G-FE-7(자릿수 전수 대조).
- **In (Tier 2)**: `sin cos tan asin acos atan exp` 7함수 화이트리스트 확장 — `ALLOWED_FUNCTIONS`(sandbox.ts:45-62) + `*Dependencies` 선택 임포트(sandbox.ts:92-111) 1:1 동기(sandbox.ts:16·90 규약). ★**asin·acos 2종 = S6 표본 외 추가**(표본 내 수요 0건 — 근거는 역률각 역산 `theta=acos(pf)` staple 선제 대비. 표본 근거 없음을 명시 라벨 — Q2 (b)로 축소 선택 가능).
- **Out (Tier 3 별건 — 본 plan 금지)**: 복소수 타입(대칭좌표법)·sinh/cosh(장거리선로 — 진짜 blocker는 γ 복소, S6 §5 Tier 3 귀속 정정)·s-도메인 기호(제어 — lcapy형 별건 feasibility). **D-1 복소수 방침(카드 Q3 "romanize 락 선행" 대상)은 본 plan이 아니라 후속 별건 문서** — 본 plan의 삼각/지수 확장분은 축 A 표기 규약과 독립(카드 §5 D-1 "삼각/지수 확장분은 축 A와 독립").
- **Out (기타)**: D1 157 산식 재적재·WS-3c 드리프트 55건 화해(별건 결재 진행 중 — §6 시퀀싱만 다룸) / KaTeX 표시층(카드 Q1 별건) / 임베딩(S9 게이트).

### 0.3 불변 전제 (위반 = 산출물 무효)

1. **동적 코드 실행 절대 금지** — math.js AST만(Hard Limit). throwing stub(evaluate/compile/simplify 등 10종)·`ALLOWED_NODE_TYPES` 무변경.
2. **LLM 수식 계산 0** — 확장 후에도 계산 = Formula Engine 단일 경로. Constants = DB 쿼리로만.
3. **1호 무회귀** — 손해평가 68식 산출값 byte-diff 0 (G-FE-1). 확장으로 1호 golden 1건이라도 변하면 STOP·보고.
4. **범용 계층 시험 분기 금지**(Hard Rule 15) — sandbox 확장은 함수 집합 additive만, `if (examId)` 류 분기 0. 각도 규약은 데이터·저작 규약으로 처리(§4-C 정합).

## §3 설계 (코드 0 — 결재 후 착수 시 사양)

### 3-1 Tier 1 — π·e 상수 적재 [L3 상수]

- (rev2 정합화) 권고 경로 = **엔진 내장 — constants DB 미적재**. Hard Limit "Constants는 DB 쿼리로만"은 **교재 유래 도메인 상수**(65%·보험료율 등) 규율이며 수학 보편 상수(π·e)의 정본은 math.js 내장값 — DB 병행 적재는 이중 진실원 서식지. (b) 선택 시에만 범용 category 신설이 하위 결정으로 활성화.
- **값 정밀도 결정 필요**: full double(`Math.PI` 15자리) vs 교재 관행 3.14/3.1416 — 기출 정답 역검증으로 확정(전기기사 정답 매칭이 3.14 전제인 문항 존재 가능 — 추정, W5 실측 대상). 후보: full double 저장 + 문항별 반올림은 `resultPrecision`(engine.ts:108) 처리.
- 주입 경로(§2-(e)) 3옵션: (i) 호출자가 constants DB 조회 후 inputs로 전달(엔진 코드 0, 호출 규약 문서화) / (ii) variablesSchema에 π 상수 변수 선언(저작 규약) / (iii) 엔진 내장 `piDependencies`+`eDependencies`(코드 확장 — Tier 2와 동일 클래스로 흡수). **권고 = (iii) Tier 2에 흡수** — 이유: (i)(ii)는 π를 "입력 변수"로 위장해 저작·호출마다 오입력 표면 생성, (iii)은 단일 지점. 단 (iii) 채택 시 `safeParse` 변수 추출에서 `pi`/`e` 제외 처리 필요(코드 접촉 +α) — Q1 결재.

### 3-2 Tier 2 — 삼각 6 + exp 확장

- `ALLOWED_FUNCTIONS` += `sin cos tan asin acos atan exp` (+Q1-(iii) 시 상수 심볼 `pi e`), `create({...})` += 대응 `*Dependencies` — sandbox.ts:16·90의 1:1 동기 규약 준수, 헤더 주석 함수 수 정정(현 "17" stale 동시 해소).
- **불변 보존**: throwing stub 10종(:117-151)·`ALLOWED_NODE_TYPES` 5종(:167-173)·`SAFE_SYMBOL_PATTERN`·`BLOCKED_SYMBOL_NAMES`·MAX 한도 3종(:253-255, 변경 시 ADR-029 §2.4 절차) 전부 무변경. 동적실행 금지(math.js AST만) 재확증 = §5 G-FE-5.
