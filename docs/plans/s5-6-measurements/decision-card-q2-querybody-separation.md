## 1. 한 줄 결정 요청

> **G-S5 측정 시, 골든의 query 를 "출제 본문(학습자가 실제로 검색창에 칠 텍스트)"만으로 할 것인가, 아니면 지금처럼 "본문 + 답안키 + 채워진 표 + 출제자 해설" 통째로 할 것인가?**

현재는 **통째**다. 그래서 measurable 7 중 3건이 query>500자로 거부돼 **분모가 4로 줄었고**, 하필 그 3건이 graph 가 빛날 multi-hop 문항이다.

---

## 2. 문제 (실코드 메커니즘 — 검증됨)

| 단계                 | 사실 (file:line)                                                                                                          |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| 러너가 보내는 query  | `query: it.content` — 골든 `content` **전체**를 그대로 전송 (`scripts/measure-s5-6-multihop-accuracy.ts:117`)             |
| route 의 제한        | `query: z.string().min(1).max(500)` — 500자 초과 시 **400 거부** (`apps/api/src/search/graph-search-route.ts:79`)         |
| `content` 안에 든 것 | 출제 본문(발문+빈칸/보기) **＋ 답안키**(`➡ 역병`, `① 120` 등) **＋ 채워진 표** **＋ 출제자 해설**(`※ …`) 이 **한 덩어리** |

→ 즉 **route 제한이 잘못된 게 아니라, 골든 query 가 "문제 한 장 통째"라서** 길이를 넘긴다. 실제 학습자는 정답·해설을 검색창에 치지 않는다.

## 3. 증거 — measurable 7건의 query 글자 수 (= content 길이)

| 문항                  | hop       | query 글자수 | ≤500?     | expected 노드 | graph 표적?                           |
| :-------------------- | :-------- | -----------: | :-------- | ------------: | :------------------------------------ |
| Q-2019-05-031         | single    |           76 | ✅ 측정됨 |       1 (LAW) | ✗ (vector 자명)                       |
| Q-2022-08-045         | single    |          336 | ✅ 측정됨 |       1 (LAW) | ✗                                     |
| Q-2023-09-045         | single    |          192 | ✅ 측정됨 |       1 (LAW) | ✗                                     |
| **Q-2025-11-2ND-012** | **multi** |          391 | ✅ 측정됨 |             5 | **○ (그런데 이게 유일한 regression)** |
| **Q-2025-11-2ND-014** | **multi** |      **501** | ⛔ 제외   |             7 | **○**                                 |
| **Q-2025-11-2ND-004** | **multi** |          595 | ⛔ 제외   |             1 | **○**                                 |
| **Q-2025-11-2ND-015** | **multi** |          922 | ⛔ 제외   |             3 | **○**                                 |

**핵심 한 장:**

- 측정에 든 single-hop 3건은 전부 vector top-1 이 자명 → **graph 가 기여할 여지 자체가 없는 문항**.
- graph 가 빛날 **multi-hop 4건 중 3건(75%)이 길이로 탈락**. 남은 1건(Q-012)이 regression → 그게 −33% 헤드라인.
- **Q-014 는 501자 — 딱 1자 초과**. 원인: `content` 에 **빈칸 표**(`( ① )일 이후`)와 **정답 채운 표**(`( ①120 )일 이후`)가 **중복**으로 들어 있음. 정답표 한 벌만 빼면 한참 아래로 떨어진다.

> ⇒ 현 측정은 "graph 를 테스트했다"기보다 **"graph 표적의 75%를 빼고 잰" 것.** (감사 합의 발견 [CRIT, 4/5])

## 4. 답안키가 query 에 든 것이 일으키는 이중 피해

1. **길이 (확정)** — multi-hop 3건 제외 → graph 유효표본 **N=1** → graphOnlyRecovery 0 이 "graph 실패"인지 "표본 없음"인지 분리 불가.
2. **편향 (방향 확정, 정량 미측정)** — query 에 정답 텍스트(노드명·정답 단어)가 섞이면 **vector 검색이 정답 노드를 부당하게 잘 회수** → baseline 100% 의 일부가 아티팩트(감사 §3 합의 [MAJOR, 3/5]). 본문만 query 하면 이 오염 제거.
3. **비현실성** — 학습자는 발문을 치지 정답·해설을 치지 않는다. 현 측정은 **production 사용 패턴과 괴리**.

> ⚠️ 단 #2(편향)는 본 정책으로 **query-측 오염만** 해소. expected 선정 자체의 vector 친화(노드명 대조로 골든 선정)는 **별건 = 결재 큐 #6**(expected 를 "추론경로"로 재정의).

## 6. 권고 = **A**, 그리고 "출제 본문" 기본 정의

> 진산이 아래 정의를 그대로 승인하거나 한 줄로 수정하면, 나머지(추출·재측정)는 AI 가 자동 처리.

- **포함(본문)**: 발문 + 보기(①②③④) + 빈칸 구조(`( ① )`) + **문제가 푸는 데 주는 자료 표**(예: Q-004 의 등급별 병충해 표, Q-015 의 가입금액/가액/손해액 표 = 출제가 _준_ 데이터).
- **제외(정답·해설)**: 채워진 정답값(`➡ 역병`, `① 120`, `= 19,600,000원`), **중복된 정답표**(Q-014 의 두 번째 표), 출제자 해설/주석(`※ 이론서 …`, `복수정답 …`).
- **근거**: 학습자가 실제로 검색창에 칠 텍스트 = "정답을 모르는 상태의 문제". 정답·해설은 채점 정답지이지 query 가 아니다.

**A 채택 시 회복 추정(정직 표기 — 정확 수치는 추출 후 산출):**
Q-014(501→정답표 중복 제거 시 한참 아래) **회복 확실** / Q-015(922→워크드 풀이 제거 시 본문+자료표) **회복 유력** / Q-004(595→표가 대부분 _준_ 자료라 정답만 빼면 여전히 경계) **불확실**. ⇒ measurable **4 → 6**(보수), 최대 7.

2. **maxDepth=1 + maxDepth=2 양쪽 전수 재측정**(감사 §5 #1 — Q-012 regression 이 depth1 로 가역됨을 메인이 이미 raw 재현). 러너에 `maxDepth` 인자 추가(route 는 이미 `maxDepth` param 지원, `graph-search-route.ts:86`).

## 9. ★ 진산 인사이트 — 분리된 정답·해설의 행선지 = 근거 기반 학습 UX (2026-06-04)

진산 queryBody 확인 시 통찰: **"queryBody 는 그냥 출제된 문제일 뿐. 학습자는 문제를 보고 → 이후 정답확인·해설을 봐야 하며, 그것도 근거를 기반으로 정확하게."**

- **함의**: 측정을 위해 query 에서 제거한 정답값·해설은 _버린 것이 아니다_. 원본 `golden-pilot-approved.json` 의 `content`(불변) + `querybody-removal-log.md` 의 제거 segment 에 **보존**되어 있다.
- **제품 구조 정렬**: 결재 #2 의 `질문(queryBody) | 정답값+해설` 분리는 우연이 아니라 **학습자 흐름의 올바른 분리**다 — `① 문제 제시(queryBody) → ② 학습자 풀이 → ③ 정답확인 + 해설(근거 FK 기반·정확)`.
- **carry-over (Phase B/C)**: 보존된 정답·해설을 학습자 노출용으로 쓰려면 문항당 **구조화 필드 {question(본문), answer, explanation, sources(교재 page_ref·법조문·기출 FK)}** 가 필요. 근거 0건 = approved 불가(출처 추적성 요건). 이는 [[project_source_citation_requirement]] + 보기별/물음별 출처 라벨 [[project_multi_source_choice_basis_track]] (진산 결재 단계분리 Phase B=pilot 시범 → Phase C=545 전수 BATCH+공식해설집)와 동일 트랙. **G-S5 측정 완료 직후 Phase B 진입 결재 상신 의무**(기존 carry-over 재확인).
- **즉시 행동 없음**: 본 인사이트는 방향 확인·carry-over 기록이며, 현 측정 게이트(REMOTE 인증)와 독립. 측정 우선.
