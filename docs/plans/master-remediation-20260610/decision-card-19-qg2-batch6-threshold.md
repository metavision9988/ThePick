# 결정 카드 #19 — QG-2 BATCH-6+ 누적 산식 임계값 정의

> 작성: 2026-06-12 / 상태: **결재 대기** (임계값 = 매직넘버/L3 인접 — 수치 채택은 진산. 본 카드 = 비교표만, 코드 무변경)
> 배경: WS-2c S6가 QG-2 헤더 동기 + batchId 배선까지 완료했으나, BATCH-6+ 누적 임계 "정의"는
> 결재 사안이라 보류 후 본 카드로 상신(`MASTER_PLAN.md:133` S6 이행 기록 + `:282` §6b #19 행).
> 데드라인 = BATCH-6+ 를 파이프라인 경유로 다루는 작업(재실행·개정 사이클) 착수 전.

## ① 실코드 현황 (`apps/batch/src/qg2-validator.ts`)

- 누적 임계 정의 = **BATCH-1~5 만**: 7/30/38/53/68 (`qg2-validator.ts:35-41` CUMULATIVE_FORMULA_THRESHOLDS).
  미정의 batchId → fallback `minFormulas: 7` (`:27` + `:102` `?? QG2_THRESHOLDS.minFormulas`) = 누적 검증 약화.
- **완화(확인)**: 파이프라인 `BatchId` 타입이 BATCH-1~5 한정(`pipeline.ts:240` = `keyof BATCH_CONFIGS`,
  configs 5종 `:174-235`) → 파이프라인 경유로는 fallback(7) 도달 불가(S6 기록·리뷰 MAJOR-4 완화, `MASTER_PLAN.md:133`).
  단 `checkFormulaRegistry(batchId: string)`(`:100`)·`runQG2Validation(..., batchId: string)`(`:222`)은
  `string` 시그니처라 직접 호출로 'BATCH-6' 전달 시 무경고 7 검증.
- 카운트 대상 = `getAllFormulas()` = **formula-engine 레지스트리** (`:101-102`) — D1 적재물 카운트가 아님.
