# 결정 카드 — 승계(SUPERSEDES) 은퇴 시점 ↔ 시행시점 창 정합

> 2026-08-07 · **상태 = 결재 대기 (코드·SQL 0줄 작성)** · L3 (DB 트리거)
> 발단 = 결재 대시보드 §A #9 "권고대로 진행"(진산 2026-08-07) → **착수 전 실측에서 권고안의 결함 발견**
> RULE #5 준수: 아래는 사실 + 선택지 + 권고. 채택은 진산.

---

## 0. 왜 이 카드가 생겼나 — 승인된 권고가 그대로는 틀렸다

대시보드 §A #9 의 권고는 **(a) 0042 WHEN 절에 "승계자가 발효된 경우에만 은퇴" 추가**였다.
착수 전 변형본을 만들어 실측했더니 **blackout 을 이중 노출로 바꿀 뿐**이었다.

### 실측 (전 마이그 적용 in-memory SQLite · 재현 스크립트 §6)

시나리오: `OLD`(현행, approved, valid_from 없음) ← `NEW`(개정본, approved, **valid_from = 미래**)
가 SUPERSEDES 로 승계.

| 트리거            | 오늘 (시행 전)             | 시행일 이후                                  |
| ----------------- | -------------------------- | -------------------------------------------- |
| **현행 0042**     | **(없음)** ← 서빙 blackout | `NEW` ✅                                     |
| **권고 (a) 적용** | `OLD` ✅                   | **`OLD`, `NEW` 동시** ← 구·신 규정 동시 노출 |

### 원인 (구조적)

0042 의 두 트리거는 **이벤트 구동**이다 — `AFTER INSERT ON knowledge_edges` / `ON status_transitions`.
(a) 처럼 "승계자가 발효됐을 때만 은퇴" 조건을 걸면, 승인 시점엔 미발효라 발화하지 않는다.
그리고 **시행일이 도래해도 아무 행도 바뀌지 않는다** — SQLite 에는 시간 기반 트리거가 없다.
즉 은퇴를 실행할 **이벤트가 영원히 오지 않는다.**

> **판단**: 학습 서비스에서 "근거가 사라짐"(blackout)과 "구·신 규정이 동시에 보임"(이중 노출) 중
> 후자가 더 나쁠 수 있다. 학습자는 둘 중 무엇이 현행인지 알 방법이 없고, 시스템은 그 상태를
> 정상으로 여긴다(무음). ⇒ **(a) 단독 채택은 권고 철회.**

---

## 1. 문제의 정확한 형태

**하나의 시점 개념을 두 장치가 각각 다르게 관리하고 있다.**

| 장치                                                   | "현행"의 정의           | 갱신 시점                  |
| ------------------------------------------------------ | ----------------------- | -------------------------- |
| `is_current_active` (ADR-013 Materialized Active View) | 승계당하지 않은 것      | **승인 이벤트**            |
| `valid_from`/`valid_until` (0041 + 2026-08-06 배선)    | 오늘이 유효기간 안인 것 | **시각 경과**(이벤트 없음) |

둘이 어긋나는 구간이 정확히 **"승인됨 + 아직 미시행"** 이다. 지금까지 이 구간이 존재하지 않았던 이유는
**미시행 개정을 승인하지 않는 관행**(현 데이터: 개정 노드 4건 전부 draft) 때문이지, 장치가 막아서가 아니다.

## 2. 선택지

### (A) 발효 스윕 — (a) + 시간 이벤트 공급

(a) 조건을 넣고, **시행일이 지난 승계자의 구본을 은퇴시키는 주기 작업**을 추가한다.

- 구현: 기존 cron 인프라(`ops.yml` / scheduled worker) + 스윕 SQL + 무결성 불변식
  ("승계자가 발효됐는데 구본이 아직 활성 = 위반")
- 장점: `is_current_active` 의미 유지. 서빙 경로 무변경(성능 무영향).
- 단점: **새 실패 지점**(스윕이 안 돌면 이중 노출이 조용히 지속) → 불변식 + 알림 필수.
  스윕은 `knowledge_nodes` UPDATE = Hard Limit 화이트리스트 확인 필요.
- 규모: 마이그 1 + 스윕 1 + 불변식 1 + 테스트 + 리뷰 = **M~L**

### (B) 서빙에서 계보 해석 — 플래그 대신 시점으로 판정

`is_current_active` 를 시점 판정의 권위에서 내리고, 서빙 CORE 가
"이 계보에서 오늘 유효한 판본"을 직접 고른다.

- 장점: 시간 이벤트 불필요(구조적으로 항상 정확). 스윕 실패 같은 새 실패 지점 없음.
- 단점: **단일 진실원 CORE 에 계보 JOIN 추가** → hot path 비용 증가(현 2.35ms 에서 더). ADR-013
  전제를 건드리므로 **ADR 개정 사안**. 4~5 소비자 전부 영향.
- 규모: **L~XL**

### (C) 정책 — 시행일 전 승격 금지 (코드 0줄) ★

**미시행 개정은 승인하지 않는다.** 시행일에 승격하면 그 시점이 곧 이벤트라 0042 가 정상 발화하고,
blackout 도 이중 노출도 발생하지 않는다.

- 장점: **비용 0**. 현 관행과 이미 일치(개정 4노드 전부 draft). 오늘 당장 위험이 사라진다.
  0041/시행시점 창은 **2차 방어선**으로 남아 제 역할을 한다.
- 단점: **사람 규율에 의존** — 잊으면 다시 열린다. 그래서 기계 가드 1개는 붙여야 한다:
  **"미시행 노드의 approved 전이 차단"** 트리거(= 승격 시점에 `valid_from > today` 면 ABORT).
  이건 (A)(B) 보다 훨씬 작다(트리거 1개).
- 규모: 마이그 1(트리거 1개) + 테스트 + 문서 = **S**
- ★주의: 개정 준비 작업(미리 만들어 두기)은 draft 로 계속 가능하다 — 막는 것은 **승격**뿐이다.

### (D) 아무것도 하지 않음 — 현행 유지

- 오늘 위험 없음(도달 조건 = 미시행 승격, 현재 0건). 다만 **다음에 누가 미시행 승격을 하면
  blackout 이 무음으로 발생**하고, 그때는 원인 추적이 어렵다.
- 채택 시 최소 의무: 무결성 러너에 "계보 공백" 불변식만이라도 추가(관측).

## 3. 권고

> **(C) + 최소 기계 가드** 를 권고한다. 이유:
>
> 1. **현 관행이 이미 (C)** 다 — 데이터가 그 증거(개정 4노드 전부 draft). 새 규율을 만드는 게 아니라
>    이미 하고 있는 것을 기계가 지키게 하는 것이다.
> 2. (A) 는 "이중 노출을 막기 위해 주기 작업을 도입하고, 그 주기 작업이 실패하면 다시 이중 노출"이라
>    **실패 모드를 옮길 뿐** 없애지 못한다. 알림·불변식까지 딸려 온다.
> 3. (B) 가 구조적으로는 가장 옳지만 ADR-013 개정 + hot path 비용 + 5 소비자 영향이라
>    **STAGE 2(원문 저장) 앞에 끼워 넣을 크기가 아니다.**
> 4. (C) 를 택해도 (B) 로 가는 길이 막히지 않는다 — 나중에 시점 기반 서빙이 필요해지면
>    그때 ADR 개정과 함께 하면 된다. **되돌릴 수 없는 선택이 아니다.**
>
> 즉 **지금은 가장 싼 가드로 위험을 닫고, 구조 개편은 필요해질 때 별도 결재**로.

### (C) 채택 시 할 일 (다음 세션)

1. 마이그 `0045_block_premature_promotion.sql` — `status_transitions` BEFORE INSERT 트리거:
   `to_status='approved'` 이고 대상 노드의 `valid_from > today` 면 ABORT (메시지에 "시행일 이후 승격" 안내)
2. 0039 헤더의 blackout 경고를 "정책 (C) 로 해소됨"으로 갱신
3. 게이트: 미시행 노드 승격 시도 → ABORT / 시행일 도래 후 승격 → 통과 + 0042 정상 발화 →
   서빙이 `NEW` 단독 (blackout·이중 노출 둘 다 0)
4. 무결성 러너 불변식 1개: "활성 계보에서 구·신 동시 활성 0" (사후 관측)

## 4. 이 결정이 막고 있는 것

- **0039 production 적용** — blackout 경로가 열린 채로 부활 차단까지 걸면 복구 수단이 줄어든다.
  본 카드 결재 후 함께 적용하는 것이 안전하다.
- **STAGE 2 백필** — `valid_from` 에 값이 들어가기 시작하는 순간 이 구간이 실재하게 된다.
  즉 **본 카드는 STAGE 2 의 선결**이다.
