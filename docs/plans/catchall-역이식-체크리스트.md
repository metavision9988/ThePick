## 0. 한번에 할까, 나눠서 할까 — 결론: **나눠서. 단, 5묶음으로.**

### 한번에 하면 안 되는 이유 (물리적인 것부터)

| #   | 이유                              | 구체적으로                                                                                                                   |
| --- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 1   | **순서가 강제된다**               | 카드에 원문을 저장하기 전에는 검증 엔진이 **검사할 대상이 없다.** 순서를 바꿀 수가 없다                                      |
| 2   | **안전장치를 켜면 작업이 막힌다** | 지금 꺼져 있는 장치를 켜는 순간, 지금까지 통과하던 편집이 차단된다. 짝이 되는 장치와 **같이** 켜지 않으면 작업 자체가 멈춘다 |
| 3   | **결재가 병목이 된다**            | 데이터 구조를 바꾸는 건 진산 승인이 필요하다. 한꺼번에 몰면 승인 한 번이 늦어질 때 전부가 선다                               |
| 4   | **효과를 측정할 수 없다**         | 다섯 개를 동시에 넣으면 좋아진 게 어느 것 때문인지 모른다. 다음에 뭘 더 할지 정할 근거가 사라진다                            |
| 5   | **라이브 서비스가 돌고 있다**     | 학습자 검색 경로를 건드리는 작업이 섞여 있다. 다른 변경과 섞으면 문제가 생겼을 때 원인을 못 가른다                           |

### 그래도 **반드시 묶어야 하는 것**이 있다 (쪼개면 사고 남)

- 안전장치 수리 ↔ 짝 장치 → **같은 작업 단위**. 따로 하면 세션이 멈춘다
- 연결선 보호 ↔ 부활 차단 → **같은 파일 한 장**. 어차피 같은 자리다
- 원문 칸 만들기 ↔ 기존 카드 채우기 → **같은 흐름**. 칸만 만들고 안 채우면 _"검사 통과 = 전부 검증됨"_ 이라는 착각이 생긴다

### 그래서 이렇게 나눈다

```
STAGE 0  지금 새는 것 막기          결재 불요       1~2일     ← 오늘 시작 가능
STAGE 1  안전장치 마저 채우기        결재 1줄        2~3일
STAGE 2  ★관문 — 원문 문장 저장     결재 1줄        1~2주
STAGE 3  검증 엔진 가져오기          결재 불요       2~3주
STAGE 4  빠뜨린 것 찾기 + 자동화 준비 결재 1줄       3~4주
STAGE 5  나머지 (틈새 작업)          결재 불요       상시
```

**진산이 해야 할 일은 전 구간 통틀어 「1줄 답변 3번」이다.** 나머지는 자율 진행.
