## 진산님 워크플로우 트리거 (메모리 등록됨)

진산님이 다음 키워드 중 하나로 요청 시 Claude 가 자동으로 다음 ☐ BATCH 진행:

- "BATCH-N 적재" / "BATCH N 적재" (특정 BATCH 지정)
- "다음 배치 적재" / "다음 BATCH 적재" (로드맵 순서 자동)
- "계속 적재" / "이어서 적재"

요청 시 Claude 행동 (자동 진행):

1. 본 로드맵에서 다음 ☐ BATCH 식별
2. pdfplumber subprocess 로 해당 페이지 텍스트 추출
3. 도메인 분석 + Knowledge Graph JSON 생성 (Ontology Lock 자체 준수)
4. 진산님 즉시 검수 요청 (sample 노드 5건 / 산식 1건 교재 페이지 대조)
5. 검수 통과 시 SQL INSERT 스크립트 생성
6. wrangler d1 명령으로 D1 적재
7. 본 로드맵 체크박스 ☐ → ✅ 갱신 + 핸드오프 작성
8. 진산님이 "다음" 요청할 때까지 대기

## 검수 체크리스트 (BATCH 단위 공통, 3단계 검증)

진산님 비유: "사람으로 치면 머릿속에 넣은 지식이 제대로 되었는지 확인하는 것처럼".
DB INSERT ≠ 지식 적재 완료. 학습자가 시험 문제를 풀 수 있어야 진짜 적재 완료.

### Level 1 — 표면 검증 (DB INSERT 직전)

- [ ] **Ontology Lock** — `LAW-NNN` / `F-NN` / `INS-NN` / `CROP-NNN` / `CONCEPT-NNN` / `TERM-NNN` ID 형식 정확
- [ ] **schema-validator** — JSON 구조 (nodes / edges / formulas / constants) 통과
- [ ] **graph-integrity** — 고아 노드 0건 / 끊긴 엣지 0건 / SUPERSEDES 순환 0건
- [ ] **sample 노드 5건** — `name` 이 교재 본문 표현과 일치 (진산님 무작위 검수)

### Level 2 — 내용 정확성 검증 (DB INSERT 후)

- [ ] **qg2-validator Golden Test** — `batch-N-golden.json` 산식 정확도 100% (Formula Engine 자동)
- [ ] **page_ref 무작위 5건** — 실제 교재 페이지와 일치
- [ ] **산식 sample 1건** — `equation_template` 의 변수명이 `formulas` 레지스트리와 정확히 매칭
- [ ] **26년 개정 적용** — 교재 원본 vs 개정사항 충돌 시 `revision_changes` 명시 노드 + SUPERSEDES 엣지

### Level 3 — 학습 효과 역검증 (가장 중요, 진산님 비유 대응)

**기출문제 역추적**: 적재된 노드/산식/Constants 만으로 해당 영역 기출 문항을 풀 수 있는가.

- [ ] **기출 1~2건 자동 풀이** — 본 BATCH 영역 관련 기출문제 (2019~2025) 1~2건 식별 → 적재된 노드/산식만으로 정답 도출 시도 → 일치율 100%
- [ ] **혼동 유형 감지** — 유사 노드 간 차이가 명확한가 (예: 유과타박률 vs 낙엽률, 손해정도비율 20% vs 10%)
- [ ] **누락 페이지 식별** — 적재된 노드의 `page_ref` 합 vs BATCH 페이지 범위 — 누락 페이지가 있다면 그 페이지 본문에 적재할 노드가 정말 없는지 진산님 확인
- [ ] **출처 추적성** — 모든 노드/산식이 `page_ref` 또는 `revision_change_id` 보유 (메모리 `project_source_citation_requirement.md` 정합)

### 검증 실패 시 처리

- Level 1 실패 → JSON 재생성 (Ontology Lock 자체 준수 강화)
- Level 2 실패 → 해당 노드/산식 정정 후 재적재 (D1 신규 노드 + 이전 노드 SUPERSEDES)
- Level 3 실패 → 누락된 노드/산식 추가 적재 OR 해당 기출이 본 BATCH 외 영역 의존 (다음 BATCH 에서 처리 명시)
