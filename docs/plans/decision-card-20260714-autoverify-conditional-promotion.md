## 1. 정본 5조건 (catchall CLAUDE.md 에서 확정된 것의 플랫폼 승격)

자동 approved 는 아래 전부를 요구한다 (하나라도 미충족 = 인간 승격 경로 유지):

1. **골든 검증셋 선행 캘리브레이션** — 정답을 아는 held-out 세트로 파이프라인 오류율을 실측한
   **후에만** 자동 승격 활성화. 검증에 쓴 자료는 자동 승격 대상에서 제외 (검증용/적재용 분리).
2. **결정론 게이트 전 PASS** + 해당 도메인의 알려진 공격 클래스 방어 게이트 (예: 바이그램 G3 의
   속성-스왑 한계 → LCS 보조지표 또는 독립 이중 추출 합의). LLM confidence 자기보고 단독은
   승격 근거 불인정.
3. FAIL·경계 사례 = **사람 큐** (자동의 출구는 '승격 또는 큐'만 — 무음 폐기 금지).
4. **적재 후 상시 감사** — 자동 승격분 랜덤 표본 재검증(cron) + 질답형 검수 모듈(AI 가 원문
   하이라이트 + 초점 질문 제시) + 사용자 신고 정정 큐.
5. 오류 발견 시 해당 소스 배치 전체 재검증 + 임계 재캘리브레이션.

## 2. 시험 도메인 특수화 — GT 계층별 자동 승격 자격 (핵심 신규 설계)

시험 도메인은 이음길(조례)보다 **GT 가 강하다** (공식 기출 정답 존재). 콘텐츠 클래스별로 분류:

| Class | 콘텐츠                                            | GT                   | 자동 승격                                                                                                                                                        |
| ----- | ------------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A** | 기출 문항·공식 정답·산식(golden 검증식)           | **official GT 실재** | 🟢 V1 결정론 대조(공식 정답·golden 100% 일치) + 게이트 PASS → 자동 승격 자격. 가장 강한 클래스                                                                   |
| **B** | 지식 노드·법령 조문·상수 (원문 대조 가능)         | 원문 문서            | 🟡 게이트(원문 인용 실재성 — **catchall G3 바이그램 역이식** + 값 정합 + 무결성) + §1-1 캘리브레이션 후 조건부 자동                                              |
| **C** | 생성물: 암기법·변형문제·distractor·해설 (GT 부재) | 없음                 | 🔴 **자동 승격 불가 유지** — 역방향 검증(암기법 복원)·독립 AI 이중 합의·인간 표본 감사. 정답 100% Hard Stop 클래스(1차 정답오류 36 인시던트 교훈)는 보수 측 고정 |

검증용/적재용 분리의 시험 번역: **기출 held-out 회차** (예: 7회분 중 1~2회는 캘리브레이션 전용 —
파이프라인이 그 회차를 처리한 결과 ↔ 공식 정답 대조 = 오류율 실측. ThePick golden 방법론과 동형).

## 3. 진산 워크플로우 명문화 — "검증된 자료 인입 → 신뢰 지식화"

> 진산: "내가 그 종목 전문가가 아니라서, 검증된 자료만 전달해주면 — 정리해서 저장(벡터공간)하고
> graph 로 뽑아내되, 근거가 확실히 있어야."

이 파이프라인은 **대부분 실재**한다 (신규는 자동 승격 층):

```
진산: 검증된 원자료 전달 (교재 PDF·기출·법령 — 출처 신뢰는 인입 시점에 인간이 보증)
  → [실재] 플레이북 인스턴스화 (T4 _template) + 파서(PDF→구조)
  → [실재] LLM 추출 (스키마 강제·출처 앵커 의무) → 게이트 (G-GAP 류 + ★G3 바이그램 역이식 = 신규)
  → [실재] 이중 저장: D1 지식그래프(구조·판정·출처·개정 축) + Vectorize(의미 검색)
      ※ 역할 정확화(실측 기반): 벡터 = 이해·검색 (G-S5 baseline 73~83%) /
        그래프 = 근거 FK·temporal 거버넌스·개정 추적 — 검색 순위 강화용이 아님
        (graph-walk 3차 연속 순기여 0 실측)
  → [신규] Class A/B 자동 승격 (§1 5조건) / Class C·경계 = 사람 큐(질답형 검수)
  → [실재] Revision Watch (최신성) + 무결성 러너·백업·스모크 (항상성·안정성)
```

## 4. 4축 구현 지도 — 현존 vs 갭

| 축     | 실재 (ThePick)                                                                | 갭 (본 개정이 요구)                                                                                               |
| ------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 신뢰성 | 결정론 게이트(G-GAP·QG)·draft 거버넌스 트리거·4-Pass/5-페르소나·golden 방법론 | ①`packages/autoverify` **실물 부재**(T6 — 문서만) ②G3 바이그램 역이식 ③Class 분류기(콘텐츠 타입→승격 경로 라우팅) |
| 항상성 | 무결성 러너·D1→R2 백업·라이브 스모크·정합성 텔레메트리(DO-1)                  | ④자동 승격분 **표본 감사 cron** ⑤오류→배치 재검증 트리거                                                          |
| 최신성 | Revision Watch plan+spike·effective_date 축(0041)·SUPERSEDES                  | (설계 完 — production 적용 게이트 잔존, 기결 큐)                                                                  |
| 안정성 | Cloudflare 엣지·런북·secret 로테이션·배포 스모크 게이트                       | ⑥**질답형 검수 모듈** (admin 검수 콘솔 — catchall 과 공용 설계 가능, FRAMEWORK T6 확장)                           |

갭 ①~⑥ = catchall W1-LEDGER 의 파생 작업과 동일 모듈 계열 → **한쪽에서 검증되면 다른 쪽에
역이식** (크로스워크는 PROVENANCE 패턴). 구현 착수 = 별도 plan (L3 — 승격 경로는 콘텐츠 신뢰의
심장) + 아래 결재란.
