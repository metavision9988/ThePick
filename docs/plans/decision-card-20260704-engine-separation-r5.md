## 2. 번복의 공식 효력 범위 (Silent Pivot 방지 기록)

- **EXPANSION_GATE_DESIGN(#16) E3-1** "범용 인프라 착수 = 2호+3호 E2 졸업 후": **개정** — 단일 레포 내 `exams/` 분리·파라미터화(M1~M3)는 즉시 착수 가능 궤도로 전환. 단 **레포 밖 프레임워크 추출(B안)은 여전히 E3 예약**(이번 결재는 A안 채택이지 B안 앞당김이 아님).
- **ADR-007**: "Year 2 Phase 4" 시점 문구 → "즉시 조기집행(A안)"으로 Amend 대상. 확장 단위(모노레포 exams/)는 **유지**(supersede 아님 — 원안과 정합).
- **ADR-017**: 코드 경로(\_common) 유지. 데이터 계층은 종목별 D1 + **플랫폼 공유 D1(계정)** 신설로 재해석 — 공유 법령 D1은 해당 종목 진입 시 별도 결재.
- **ADR-036**: 서브도메인 통합이 "custom domain 통합 후 SameSite 복원 의무"를 이행하는 경로 — 조기 이행 대상으로 승격.
- **유지되는 게이트**: G-1(신규 Epic별 R1~R5), Hard Limit 전체(draft-only 인간 승격 포함 — 자체 검수 모듈은 차단 필터이지 승격 도장이 아님), 2호 종목 R3 spike(#17), L3 plan+승인 절차, 4-Pass/5-페르소나 독립 리뷰.

## 3. 확정 목표 아키텍처 (A안 + 통합 계정 + 서브도메인)

```
thepick.co.kr (임시 미정)          ← 포털: 종목 선택·통합 계정·구독 관리
├─ {exam1}.thepick.co.kr           ← 종목 웹 (Pages, 종목별 프로젝트)
│   └─ api 호출 → {exam1}-api.thepick.co.kr (종목 Worker)
├─ {exam2}.thepick.co.kr …
│
[레포 1개 (본 레포)]
├─ packages/  (코어 — 정화 후 전 종목 공유)
├─ exams/{id}/ (registry·domain·config·프롬프트·콘텐츠·플레이북 인스턴스)
├─ apps/api·web (종목 파라미터화 배포 셸)
│
[Cloudflare — 종목별 스택 + 플랫폼 공유 계층]
├─ 플랫폼 D1 1개: users/sessions/login_history/구독/webhook_events  ★통합 계정
│   └─ 전 종목 Worker에 PLATFORM_DB 바인딩 (Worker 1개가 D1 복수 바인딩 가능)
├─ 종목별: Worker 2(stg/prod) + 콘텐츠 D1 2 + Vectorize 2 + Pages
└─ 쿠키: Domain=.thepick.co.kr + SameSite=Lax/Strict → 전 종목 SSO
    (ADR-036 임시 SameSite=None 해소 — 복원 의무 조기 이행)
```

**권고 세부** (진산 "더 나은 방식 추천" 요청에 대한 답):

1. **계정은 "별도 auth Worker"가 아니라 "공유 플랫폼 D1 + shared auth 패키지"로** — 인증 스택은 도메인 결합 0 실측(clean)이라 패키지 공유가 가장 싸고, 별도 SSO 게이트웨이 Worker는 현 규모(1인 운영) 과잉. 종목 3개+ 또는 세션 스토어 병목 시 재평가.
2. **결제 웹훅은 플랫폼 계층 단일 수신** — PG 계약·webhook endpoint는 계정 단위이므로 종목별 분산 금지(1호 api가 겸임 → 종목 2개+ 시 platform Worker 분리 검토).
3. **1호 계정 데이터 이전 시점 = 플랫폼 D1 신설 시(2호 온보딩 전)** — 사용자 수가 적은 지금이 users/sessions 이전 최저비용 시점. L3(사용자 데이터) plan+승인 필수.
4. **도메인 확정 전 코드 하드코딩 금지** — 루트 도메인은 config/vars로만(임시 미정 존중).

## 4. 자체 검수 모듈 (신규 Epic 지시 — 가칭 **AutoVerify Gate**)

진산 지시의 구조화: "미리 문제와 답을 설정한 후 생성 후 검증 — AI 학습하는 것처럼" = **ground-truth-first 생성 검증** (KAE 문서 L4 ValidationGateKit + 외부리뷰 흡수 1순위 '기출 정답 대조 자동 게이트 격상'과 동일 계보).

| 층                  | 검증                                                                                                                                  | 성격               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| V1 결정론 대조      | 기출 정답표 100% 대조 · formula-engine 답 재계산 · 암기법 역방향 복원(기존 Hard Limit) · 출력 스키마 강제                             | LLM 0, 완전 자동   |
| V2 독립 AI 솔버     | **생성 컨텍스트를 차단한** 별도 솔버가 문제를 풀어 의도 정답과 일치 확인(N-솔버 다수결 가능) — 자기검증 순환(같은 편향 2회 통과) 차단 | 자동, AI 상호 견제 |
| V3 사전 설정 검증셋 | 문제·답 쌍을 **먼저** 확정한 골든셋 → 생성기 변경마다 검출율/오탐율 회귀 측정 (eval-driven)                                           | 측정 인프라        |

**불변 경계 (Hard Rule 7)**: AutoVerify = **draft 차단 필터**(불합격 자동 격리·폐기). **approved 승격은 인간** — 결정론 생성분은 샘플 감사로 강도 차등 가능(외부리뷰 메타분석 판정 그대로). 진산 "인간 검수는 별도" 발화와 정합.
**G-1**: AI 출력 정확도가 비즈니스 핵심 → **R1~R5 전수 대상**(별건 feasibility: `docs/feasibility/self-verification.feasibility.md` 작성 후 plan). 특히 V2 솔버의 오답 검출율(놓침율)은 측정 전 단언 금지.
