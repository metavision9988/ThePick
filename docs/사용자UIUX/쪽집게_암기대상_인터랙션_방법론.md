# Part 1. 암기 대상 리스트업 — "무엇을"

## 1-A. 8대 암기 유형 (이미 스키마에 정의됨: `memorization_type`)

레포의 `exam_questions.memorization_type` enum이 곧 암기 대상의 분류 체계다. 여기에 1차 예시와 주요 혼동 위험(`confusion_type`)을 붙였다.

| #   | 암기 유형            | 무엇을 외우나            | 손해평가사 1차 대표 예시                                           | 주 혼동 위험                              |
| --- | -------------------- | ------------------------ | ------------------------------------------------------------------ | ----------------------------------------- |
| 1   | **definition** 정의  | 용어의 법적·학술적 뜻    | 보험가액·초과보험·손해평가 정의 / (재배학) 춘화처리·도장현상 정의  | list_omission                             |
| 2   | **enumeration** 열거 | "N가지" 항목 나열        | 손해평가사의 업무 항목 / 재해보험 대상 재해 종류 / 원예작물 분류   | list_omission                             |
| 3   | **distinction** 구분 | 유사 개념 구별           | 고지의무 vs 통지의무 / 초과보험 vs 중복보험 / 보험가액 vs 보험금액 | positive_negative, cross_crop             |
| 4   | **condition** 요건   | 성립·행사 요건           | 고지의무 위반 해지 요건 / 보험자대위 성립 요건                     | exception                                 |
| 5   | **procedure** 절차   | 순서·단계                | 손해평가 절차 / 보험금 청구·지급 절차                              | procedure_order                           |
| 6   | **numeric** 수치     | 숫자·기한·비율·금액      | 각종 통지·청구 기한(일수) / 자기부담비율 / 지급기한                | numeric, decimal_coefficient, date_period |
| 7   | **exception** 예외   | 원칙에 대한 예외         | 고지의무 예외(보험자가 이미 안 경우 등) / 대위 예외                | exception                                 |
| 8   | **relation** 관계    | 조문 준용·개념 인과·위계 | 인보험에 손해보험 규정 준용 / 법–시행령–손해평가요령 위계          | —                                         |

> ⚠ 위 예시는 **유형을 보여주기 위한 대표값**이다. 실제 개별 항목·수치·조문은 이미 `knowledge_nodes` / `constants` / `formulas` 테이블에 구조화돼 있으므로, Part 2의 인터랙션은 그 데이터를 그대로 소비하면 된다. (LLM이 수치를 지어내지 말 것 — 레포 Hard Limit)

## 1-B. 과목별 고빈도 암기 버킷

1차는 객관식 4지선다, 3과목 75문항, 과목 40점·평균 60점(과락)이라 **과목별 최소 사수 세트**가 중요하다.

**① 상법 보험편** — 법 조문 중심

- **요건·기한(condition·numeric):** 각 의무의 성립요건과 기간·기한.
- **긍부정 함정(positive_negative):** "~하여야 한다" vs "~할 수 있다" — 스키마가 `type=LAW`에서 자동 분류하는 바로 그 축.
- **원칙–예외(exception):** `knowledge_edges type=EXCEPTION`으로 이미 쌍 추출됨.
- **유사 의무 구분(distinction):** 고지/통지/손해방지/위험유지 의무의 시점·대상·위반효과.
- **준용(relation):** `type=CROSS_REF` — 인보험↔손해보험 준용 범위.

**② 농어업재해보험법령** — 숫자·절차 중심

- **수치·기한(numeric·date_period):** `constants category=date`의 서로 다른 기한들.
- **절차 순서(procedure):** `type=PREREQUISITE` 3개+ 체인 = 순서 혼동 위험.
- **열거(enumeration):** 대상 품목·재해·기관 권한의 나열 항목.
- **법령 위계(relation):** 법 → 시행령 → 손해평가요령(고시)의 층위.

**③ 농학개론(재배학·원예작물학)** — 용어·분류·수치

- **정의·용어(definition):** 생리·재배 용어.
- **분류·열거(enumeration):** 작물·번식·병해 분류.
- **수치(numeric):** 생육 적온·pH·시비량 등 범위값.
- **작물 간 교차(cross_crop):** `type=DIFFERS_FROM` — 같은 조사명·다른 기준 쌍(가장 잘 틀리는 함정).

## 1-C. "가장 잘 틀리는" 8대 혼동 유형 (방어 우선순위)

이미 자동 감지되는 `confusion_type`이 곧 암기 실패 지점이다. Part 2의 인터랙션은 이 8개를 정조준해야 한다.

`numeric`(숫자) · `decimal_coefficient`(소수 계수) · `date_period`(날짜/기간) · `positive_negative`(긍부정) · `exception`(예외) · `procedure_order`(절차 순서) · `cross_crop`(작물 교차) · `list_omission`(나열 누락)

# Part 2. 암기 인터랙션 방법론 리스트업 — "어떻게"

> 원리는 하나로 수렴한다: **읽게 하지 말고 꺼내게 하라(active recall).** 능동 인출은 다시 읽기보다 50~150% 효과적이고, 빵꾸노트(클로즈)·플립·오클루전은 전부 "정답을 보기 전에 스스로 생성"하게 만드는 같은 원리의 변주다. 아래는 그 변주들의 카탈로그다.

각 항목: **핵심 동작 · 근거 · 적합 암기유형 · 방어 혼동유형 · 모바일 · 데스크탑 · 주의**

### M1. 빵꾸노트 (점진적 공개 클로즈) ★사용자 지정

- **동작:** 개념 설명문의 핵심 용어·수식·수치에 빈칸 → 사용자가 먼저 떠올린 뒤, **탭하면 서서히(페이드/블러 해제) 드러남.**
- **근거:** 생성 효과. "foot-s\_\_e"에서 답을 생성한 사람이 통째로 본 사람보다 나중 회상이 높다.
- **적합:** definition · relation · numeric · 개념문장. **방어:** list_omission · numeric.
- **모바일:** 빈칸 탭→페이드 인. 길게 누르면 초성 힌트. 여러 빈칸은 순차 공개.
- **데스크탑:** 호버 미리보기 없이 클릭 공개 / Space로 다음 빈칸. 문단 전체를 한 화면에.
- **주의:** 한 카드 빈칸 과다 금지(원자성). 항상 **답 생성 시도 후** 공개하도록 순서 강제.

### M2. 셀프 채점 플립 (Q→A 뒤집기 + 4단계 평가)

- **동작:** 앞면 질문 → 스스로 답 → 뒤집어 정답 확인 → 모름/애매/알았음/쉬움 평가 → FSRS가 간격 결정.
- **근거:** 테스트 효과 + 간격 반복. FSRS는 SM-2보다 20~30% 적은 복습으로 같은 정착.
- **적합:** definition · condition · distinction. **방어:** 전반.
- **모바일:** 카드 탭으로 플립, 하단 엄지영역에 4버튼(44px). 스와이프로 평가도 가능.
- **데스크탑:** Space=플립, 1~4 키=평가. 키보드 리듬으로 대량 처리.
- **주의:** 정답을 먼저 노출하지 말 것(플립 전 답 안 보이게).

### M3. 도해 오클루전 (Image/Diagram Occlusion)

- **동작:** 구조도·절차 플로우·조문 위계도의 라벨을 가림 → 탭할 때마다 **하나씩** 드러남.
- **근거:** 공간·구조 인출 + 생성 효과. (※ "시각형 학습자라서"가 아님 — 학습스타일 매칭은 근거 없음.)
- **적합:** procedure · relation · enumeration · (재배학) 도해. **방어:** procedure_order · list_omission.
- **모바일:** 가림 박스 탭→공개, "다음 가림" 버튼으로 순회.
- **데스크탑:** 클릭 공개 / 화살표키 순회. 큰 도해를 넓게.
- **주의:** 한 도해에 가림 과다 금지. 순서가 의미 있으면 순차 공개.

### M4. 혼동 페어 대비 (A/B 차이축 클로즈)

- **동작:** 헷갈리는 쌍을 나란히, **다른 축만** 빈칸 → 채우기. (예: 고지의무 vs 통지의무의 "시점" 칸)
- **근거:** 대비 학습 + 인터리빙. 차이를 스스로 생성해야 구분이 각인.
- **적합:** distinction. **방어:** positive_negative · cross_crop · exception.
- **모바일:** 상하 2단, 차이 칸만 탭 공개.
- **데스크탑:** 좌우 2열 동시 비교.
- **주의:** 같은 축(동일한 부분)은 회색 처리해 차이에 주의 집중.

### M5. 숫자·기한 표 클로즈 (Table Cloze)

- **동작:** 기간·비율·금액 표에서 셀을 **무작위 마스킹** → 채우기. 오답 셀만 다음 회차 재출제.
- **근거:** 표 지식은 산문 암기 시 붕괴 → 표째 인출이 시험(숫자 바꿔치기 함정)에 직결.
- **적합:** numeric · date_period. **방어:** numeric · decimal_coefficient · date_period.
- **모바일:** 셀 탭 입력(숫자 키패드). 가로 스크롤 최소화하도록 열 압축.
- **데스크탑:** Tab 이동으로 연속 입력, 전체 표 한눈.
- **주의:** 유사 수치를 같은 표에 모아 대비(혼동 표적화).

### M6. OX 반전 드릴 (긍부정 함정)

- **동작:** 조문 문장을 랜덤하게 **긍정↔부정으로 뒤집어** 참/거짓 판정.
- **근거:** "~하여야" vs "~할 수 있다" 함정을 반복 노출로 자동 판별.
- **적합:** condition. **방어:** positive_negative.
- **모바일:** 좌/우 스와이프 = O/X. 빠른 연속.
- **데스크탑:** ←/→ 키. 타이머로 스피드.
- **주의:** 오답 시 "무엇이 뒤집혔는지" 즉시 하이라이트.

### M7. 순서 재배열 (Drag to Order)

- **동작:** 절차 단계를 뒤섞어 제시 → 드래그로 순서 맞추기 → 스냅 피드백.
- **근거:** 절차 지식의 능동 재구성.
- **적합:** procedure. **방어:** procedure_order.
- **모바일:** 세로 드래그 리스트(핸들 44px).
- **데스크탑:** 드래그 또는 번호 입력. 여러 절차 동시.
- **주의:** 3~7단계로 청킹(작업기억 한계).

### M8. 매칭·연결 (Drag to Match)

- **동작:** 용어↔정의, 개념↔요건을 선으로 연결.
- **근거:** 관계 인출 + 열거 커버리지 점검.
- **적합:** relation · enumeration · definition. **방어:** list_omission.
- **모바일:** 좌우 탭-투-연결(드래그 대신 탭 2회).
- **데스크탑:** 드래그 라인. 항목 많을 때 유리.
- **주의:** 항목 6개 이하 유지.

### M9. 점진적 힌트 사다리 (Graduated Cueing)

- **동작:** 막히면 힌트를 **단계적으로** 요청 — 초성 → 첫 글자 → 글자수 → 첫 어절. 힌트를 쓸수록 다음 복습 간격 짧게.
- **근거:** 오류 유발 인출 + 최소 단서 생성이 기억을 강화.
- **적합:** definition · numeric · enumeration. **방어:** list_omission.
- **모바일/데스크탑:** "힌트" 탭/키 반복. 사용 힌트 수를 FSRS에 반영.
- **주의:** 즉시 정답 버튼은 최후에만.

### M10. 백지 인출 / 블러팅 (Free Recall)

- **동작:** 참고자료 차단 → 아는 것을 **백지에 전부** 쏟아냄 → 모범답 공개 → 커버리지로 자가채점.
- **근거:** 가장 강한 인출 부하. 열거·정의 세트 통암기에 강력.
- **적합:** enumeration · definition · procedure. **방어:** list_omission.
- **모바일:** 텍스트 입력 또는 음성(M12)로 대체.
- **데스크탑:** 넓은 입력창 + 모범답 나란히 diff.
- **주의:** 채점은 "정확 일치"가 아니라 **항목 커버리지**로.

### M11. 속도 인출 (타이머 + 오토리빌)

- **동작:** 필수 카드 연속 인출, 문항당 목표 시간(1차 기준 ≈72초). 시간 초과 시 자동 공개.
- **근거:** 아는 것과 시간 내 꺼내는 것은 다름 — 인출 자동성 훈련.
- **적합:** 전 유형(정착 후 단계). **방어:** 전반(속도 함정).
- **모바일:** 상단 얇은 진행 바(빨강 강조 금지 — gray→indigo).
- **데스크탑:** 키보드 연타로 고속. 평균 응답시간 담백 표시.
- **주의:** 신규 학습엔 쓰지 말 것(정착 후 전환).

### M12. 구술 인출 / 티치백 (Speak-to-Recall)

- **동작:** 개념을 소리 내어 설명 → 녹음/전사 후 모범답과 대조(파인만 기법).
- **근거:** 출력 부하 극대화 + 사각지대 노출.
- **적합:** definition · relation. **방어:** — .
- **모바일:** 마이크 버튼(이동 중 학습).
- **데스크탑:** 타이핑 요약으로 대체 가능.
- **주의:** 선택 기능. 조용한 환경 전제.

### M13. 두문자어·연상 표면화 (Mnemonic Surfacing)

- **동작:** 레포의 mnemonic 엔진(역방향 검증 통과분)을 **주 인출 실패 시 힌트로만** 노출. 기본 접힘.
- **근거:** 두문자어·연상은 강력하나 오적용 시 독 → 검증분만, 의존 방지.
- **적합:** enumeration · numeric. **방어:** list_omission · numeric.
- **모바일/데스크탑:** 카드 하단 "💡 암기법" 접이식.
- **주의:** 역방향 검증 실패분 폐기(Hard Limit 준수).

### M14. 스와이프 리뷰 덱 + 스트릭 (습관 계층)

- **동작:** due 카드를 한 장씩, 스와이프=평가. 연속일 히트맵.
- **근거:** 매일 짧게가 길게보다 중요 — 습관화가 간격반복의 전제.
- **적합:** 전 유형(복습 흐름). **방어:** 전반.
- **모바일:** 네이티브 스와이프(주력 80% 사용자).
- **데스크탑:** 키보드 흐름 + 히트맵 위젯.
- **주의:** 폭죽·트로피 금지(토큰). 스트릭은 담백한 그리드로.

### M15. 조건 분기 시뮬레이터 (Branch Tree)

- **동작:** 시점·조건에 따라 결론이 갈리는 규칙을 인터랙티브 분기트리로 따라가게.
- **근거:** 조건부 규칙의 능동 시뮬레이션.
- **적합:** condition · procedure. **방어:** exception · procedure_order.
- **모바일:** 단계별 선택 카드.
- **데스크탑:** 전체 분기도 조망 + 클릭 탐색.
- **주의:** 분기 3단계 이내로.

---

## 2-A. 암기유형 → 인터랙션 매핑 (기존 매트릭스의 하위층)

레포의 "혼동유형 × 암기법" 매트릭스 아래에 **인터랙션 층**을 붙인 것.

| 암기유형         | 1순위 인터랙션          | 2순위                   |
| ---------------- | ----------------------- | ----------------------- |
| definition 정의  | M1 빵꾸노트             | M2 플립 / M9 힌트사다리 |
| enumeration 열거 | M10 백지인출            | M8 매칭 / M13 두문자어  |
| distinction 구분 | M4 혼동 페어            | M6 OX / M2 플립         |
| condition 요건   | M15 분기 시뮬           | M6 OX                   |
| procedure 절차   | M7 순서 재배열          | M3 오클루전             |
| numeric 수치     | M5 표 클로즈            | M1 빵꾸노트 / M9        |
| exception 예외   | M4 혼동 페어(원칙-예외) | M15 분기                |
| relation 관계    | M3 오클루전(위계도)     | M8 매칭                 |

## 2-B. 모바일 vs 데스크탑 치트시트

|           | 모바일(80%)                   | 데스크탑(20%)           |
| --------- | ----------------------------- | ----------------------- |
| 공개      | **탭**-투-리빌, 길게눌러 힌트 | 클릭 / **Space**        |
| 평가      | 하단 44px 버튼 or 스와이프    | **1~4 키**              |
| 대비(M4)  | 상하 2단                      | 좌우 2열 동시           |
| 순서·매칭 | 탭 2회 연결, 세로 드래그      | 드래그 정밀 / 번호 입력 |
| 도해(M3)  | 박스 탭 순회                  | 화살표키 순회, 큰 화면  |
| 백지·구술 | 음성 입력                     | 넓은 입력창 + diff      |
| 강점      | 이동 중 짧은 반복, 습관       | 대량 고속 처리, 조망    |

## 2-C. 구현 우선순위 (기존 자산 기준)

이미 있는 `FillBlank` + `FSRS` + `mnemonic_cards` + `confusion` 감지를 재사용해 아래 순으로.

1. **M1 빵꾸노트** — FillBlank 확장(탭 점진 공개 + 힌트 사다리 M9 병합).
2. **M2 플립 + FSRS 4평가** — 기존 SRS에 self-grade UI.
3. **M5 표 클로즈 / M4 혼동 페어** — numeric·distinction 방어(과락 직결).
4. **M3 오클루전** — 절차·위계·재배학 도해.
5. **M11 속도 인출 / M14 스와이프 덱** — 정착 후 자동성·습관.
6. 나머지(M6·M7·M8·M10·M12·M13·M15)는 유형별 필요 시 추가.

### 한 줄 요약

외울 것은 이미 스키마의 **8유형(정의·열거·구분·요건·절차·수치·예외·관계)** 으로 정의돼 있고, 외우게 하는 법은 전부 **"보기 전에 스스로 꺼내게 하는"** 인터랙션(빵꾸노트를 필두로 한 15종)으로 수렴한다. 각 인터랙션을 8유형·8혼동유형·모바일/데스크탑에 매핑해 두었으니, 데이터는 그대로 흘려보내면 된다.
