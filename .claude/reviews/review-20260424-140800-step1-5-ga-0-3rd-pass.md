## 🟠 신규 MAJOR 2건

### F1. retentionDays 입력 검증 부재

- `rate-limit-gc.ts:39` `const retentionDays = options.retentionDays ?? 2;`
- `retentionDays = 0` → 현재 분 직전까지 모든 활성 bucket 즉시 삭제 → rate-limit 무력화
- `retentionDays = -1` → cutoff 미래 시각 → 생성되는 족족 삭제
- `retentionDays = NaN` → `new Date(NaN).toISOString()` throw → scheduled catch 가 로그만 남긴 채 cron 다음 주기까지 GC 0회

**수정**: `Number.isFinite + Number.isInteger + retentionDays >= 1` 검증 + 단위 테스트 3건 (0/-1/NaN)

### NEW-S2. 200/201 vs 404/429 타이밍 분포 비대칭

- 404/429 는 sleepJitter 50~150ms, 정상 200/201 은 즉시 (5~30ms D1 latency)
- 양봉(bimodal) 응답 시간 분포 → 공격자가 노드 ID 존재 여부 통계적 추정 가능
- 1000 회 시도 + t-test 로 구분 가능하나 rate-limit 20/min 이 50분 강제 → 실효 리스크 LOW
- 해결안: 200 에도 jitter 또는 jitter 분포를 D1 p99 보다 크게 (200~400ms, UX 부담 ↑)
