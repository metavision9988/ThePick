
## 6. Devil's Advocate (채택 — 이번 처분으로도 남는 것)

1. **"현 데이터로 행위 변화 0 = 안전"은 가장 위험한 근거다.** `valid_*` 가 0/857 이라는 말은,
   신설 게이트 9개가 production 에서 한 번도 발화하지 않을 것이라는 뜻이다
   (★2R 정정: "트리거 10개"는 틀렸다 — 순증 9 + 기존 은퇴 트리거 2개 재생성이며,
   **재생성분은 `valid_*` 가 전부 NULL 이어도 엣지 INSERT 마다 상시 발화한다**). 첫 발화는 Revision Watch
   Phase 2 백필 중에 온다 — 즉 실전 데뷔가 "대량 스크립트가 중간에 ABORT 되는 순간"이다.
   무회귀는 안전의 증거가 아니라 **미검증의 다른 이름**이며, 그래서 L-3(런북 pre-flight)가 필요하다.
2. **로컬 하네스 ≠ D1.** 재현·검증은 전부 `node:sqlite` 3.50 이다. D1 의 SQLite 버전과
   `date('now','+9 hours')` 동작이 동일하다는 것은 **가정**이지 실측이 아니다.
   → #10 적용 시 라이브 1-쿼리 확인(`SELECT date('now','+9 hours')`)을 절차에 넣을 것(비용 XS).
3. **0046 도 "문이 넷은 아닌가"에 답하지 못한다.** ★2R 이 이 경고가 옳았음을 실물로 증명했다 —
   §"막지 않는 것"에 빠져 있던 5번째(승격 후 강등)를 2R 이 찾아냈다. 이번에 셋을 찾은 방법은 전수 증명이 아니라
   다각 재현이었다. 0046 헤더의 "막지 않는 것" 4항은 **알려진 미커버**일 뿐, 미지의 경로가 없다는
   보장이 아니다. 그 보장은 러너 배선(L-4)이 상시 관측으로 대체해야 한다.

## 3R-C1 (CRITICAL) — 2R 이 고친 fail-open 을 2R 정규식이 **다시 열었다**

`normalizeDate` 의 tail `(?:[T ].*)?` 가 구분자 뒤 **임의 문자열**을 통과시켰다. 실측 fail-open 11건:

```
vf="2026-08-15 시행" / "2026-08-15 (시행)" / "2026-08-15 00:00:00 KST"
   "2026-08-15T99:99:99" / "2026-08-15T00:00:00+0900"
   ★"2026-08-15T00:00:00+09:00"  ← 오염이 아니라 **정상 ISO 오프셋**
      (SQLite 는 UTC 로 환산해 하루 앞 날짜로 판정 → 서빙 제외, 관측기는 head 10자만 보고 "서빙 중")
end-to-end: 실 서빙 SQL = []  (blackout)  ↔  관측기 anomalies = []  ⇒ gatePass=true (무증상)
```

**처분**:

1. 정규식을 **닫힌 형태**로 — `YYYY-MM-DD` + 선택적 `[T|공백]HH:MM[:SS[.f]][Z]`, **오프셋 표기 거부**,
   시각 범위(HH>23·MM>59·SS>59) 거부. 즉 "SQLite 와 같은 답이 확실한 형태만 수용, 나머지는 미서빙".
2. ★**구조적 처분 — 차등 테스트 신설** `scripts/__tests__/effectivity-mirror-differential.test.mjs`:
   실제 SQLite 에 서빙 SQL 을 돌려 TS 미러와 **54조합 1:1 대조**하고, **fail-open 이 1건이라도 나오면 red**.
   (fail-closed 방향은 허용 — 시끄러운 것은 안전하고 조용한 것이 위험하다.)
   **변이 7 실측**: 2R 개방형 정규식으로 되돌리자 즉시 red 이며 위 5개 문자열을 이름까지 지목했다.

   ★이 테스트가 진짜 처분이다. 미러 결함이 **세 라운드 연속** 살아남은 이유는 매번 **손으로 고른
   문자열 2~3개**로 손 미러를 검증했기 때문이다. 이제 손이 아니라 SQLite 가 채점한다.

## 3R-M1 (MAJOR) — `is_current_active = 1` 조건이 만든 **stale 노출** (택한 대가)

`A sup B sup C` 에서 최신본 A 가 **먼저** 승인되면 B 가 그 시점에 은퇴하고, 뒤늦게 B 를 승격해도
C 를 은퇴시키지 못한다 → 서빙 `[A, C]` (0046 이전에는 `[A]` 단독). 구식 원본이 최신본과 나란히 노출된다.

- **조건을 빼면 반대로 blackout** 이 난다(G-0046-10 이 고정) → **알고 택한 트레이드오프**.
- 처분 = **현재 동작을 테스트로 고정**(`G-0046-11`) + 0046 헤더 §"막지 않는 것" **⑦ 등재**.
  "몰랐다"와 "알고 택했다"의 차이를 코드와 문서 양쪽에 남긴다.
- 관측 공백도 함께 기록: `LINEAGE_DUAL_ACTIVE` 는 엣지 국소라 이 상태를 보지 못한다(보강 = 별건).
