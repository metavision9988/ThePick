### 확인 (PASS 증거)

1. **`d1-trigger-verify.test.ts:421-429` — `PRAGMA table_info` `.find()` null 안전 처리**
   - 코드: `cols.find((c) => c.name === 'batch_run_id')?.type` — optional chaining 사용. `find` 가 undefined 반환 시 `?.type` 이 undefined 를 돌려주며 `.toBe('TEXT')` 가 실패 메시지로 가시화. null crash 없음.
   - 동일 패턴이 `source_id` 검증에도 적용. better-sqlite3 12.4.x 에서 `PRAGMA table_info` 는 컬럼 부재 시 해당 name 행 미존재 — optional chaining 이 정확한 방어.

2. **`d1-trigger-verify.test.ts:432-441` — `PRAGMA index_list` partial 컬럼 검증**
   - `partial: number` 타입 명시 + `expect(target?.partial).toBe(1)` 검증. better-sqlite3 의 `PRAGMA index_list` 는 SQLite 3.8.9+ 에서 `partial` 컬럼을 포함. partial=1 은 `WHERE` 절 인덱스 의미. 0016 마이그레이션의 `WHERE batch_run_id IS NOT NULL` 절이 올바르게 반영됨 확인.

3. **`d1-trigger-verify.test.ts:443-447` — `idx_knowledge_nodes_batch_run_id` 단독 인덱스 검증**
   - `indexes.some(idx => idx.name === 'idx_knowledge_nodes_batch_run_id')` — 존재 여부만 검증. recover 시 row scan 방어 인덱스가 실제로 존재함을 독립 PRAGMA 로 검증.

4. **`d1-trigger-verify.test.ts:450-461` — partial UNIQUE `batch_run_id IS NULL` 다중 허용**
   - 동일 `source_id='p403#NODE-A'` + `batch_run_id=NULL` 인 노드 3개 INSERT 모두 성공. `COUNT(*) === 3` 검증. SQLite partial index 의 NULL 제외 동작 정합 — Year 1 적재 전 NULL row 다수 존재 시 UNIQUE 충돌 0건.

### 반론 (Devil's Advocate)

**PRAGMA index_list `partial` 컬럼 의존 — Cloudflare D1 환경 동작 미검증**
