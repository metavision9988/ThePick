## 신규 CRITICAL 1건 — S-1 (해소됨)

### 🔴 S-1. `/duplicate column name/` 정규식이 신규 migration 타이포 silent skip

**원 지적**:

- SQLite 실측: `CREATE TABLE t (id, status TEXT, status TEXT)` → `duplicate column name: status`
- ALTER TABLE 재실행(의도 idempotent) 과 CREATE TABLE 내부 컬럼 타이포(버그) 가 **동일 에러 메시지**
- 정규식으로 구분 불가 → 타이포 시 migration silent pass → 테이블 미생성 → 이후 CLI "no such table"
- 로컬 silent pass + staging `wrangler d1 migrations apply` 는 삼키지 않음 → **로컬-staging 동작 불일치** (새벽 3시 on-call)

**해소 방식**: 정규식 유지하되 모든 skip 에 `console.warn` 추가

- `local-db.ts:66` — skip 시 `[migrations] idempotent skip: {fileName} — {msg}` 출력
- CREATE TABLE 타이포 케이스에서도 로그가 남아 **silent 아님** (디버깅 경로 확보)
- 근본 해결 (TD-052: migration `CREATE TABLE IF NOT EXISTS` 또는 `__drizzle_migrations` 해시 추적) 은 가-1 진입 전 처리
- CLAUDE.md "빈 catch 금지 — 에러 로깅 + 전파/폴백" 정신 준수

**검증 증거**:

```
$ thepick-batch list --target-type=node  # 재실행
[migrations] idempotent skip: 0002_1st_exam_extension.sql — duplicate column name: exam_scope
[migrations] idempotent skip: 0007_users_strict_hardening.sql — duplicate column name: name
── 0 rows (knowledge_nodes)
```
