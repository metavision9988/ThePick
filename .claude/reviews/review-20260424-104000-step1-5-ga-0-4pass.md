## 중복 제거 후 실질 CRITICAL (5건)

### 🔴 CR-1. `apps/batch/bin/batch.ts:341-346` — `list` 명령이 항상 0행 반환

**출처**: Pass 1 Surgeon

`stmt.run<{...}>()` 호출이지만 `local-db.ts:101-110` 의 `run()` 구현은 `results: [] as T[]` 로 빈 배열을 하드코딩 리턴 (changes/last_row_id 만). SELECT 문을 run 으로 실행하면 행이 버려짐.

**재현**: `thepick-batch list --target-type=node` → 항상 0행 (DB에 데이터 있어도).
**수정**: `stmt.all<{...}>()` 사용. D1 Workers 환경에서도 동일 원칙.
**예상 공수**: 5분

---

### 🔴 CR-2. `apps/api/src/progress/rate-limit.ts:50-67` — UPSERT + SELECT race + enumeration oracle

**출처**: Pass 1 Surgeon / Pass 3 Advocate / Pass 2/4 보완 — **3개 에이전트 동시 지적**

- UPSERT 후 별도 SELECT로 count 재조회 = 2 round-trip. 동시 요청 시 두 SELECT가 서로의 증가분을 봐서 실측 한도가 80~100/min 으로 확장
- 60 req/min × 60 = 3,600 req/hr 열거 여전히 가능. 교재 16,000 노드 이틀이면 전수 스캔
- 429 응답 자체가 "한도 직전 가치 요청 있었음" 메타-oracle

**수정 (단계)**:

1. 즉시: `INSERT … ON CONFLICT DO UPDATE SET count=count+1 RETURNING count` 단일 쿼리 (D1 지원 확인)
2. 추가 방어: 404 연속 실패 카운트 별도 컬럼 + 지수 백오프
3. `limitPerMinute` review 라우트 맥락 10~20으로 하향

### 🔴 CR-3. `apps/api/src/db/schema.ts` ↔ `migrations/0012_rate_limits.sql` — Drizzle schema 누락

**출처**: Pass 2 Architect / Pass 2/4 보완 — **2개 에이전트 동시 지적, ADR-001 위반**

`rate_limits` 테이블이 Drizzle schema.ts 에 0건 정의. 주석 "13 tables" 와 실제 14개 테이블 불일치. `drizzle-kit generate` 재실행 시 rate_limits 가 **drop migration** 으로 자동 생성 → 운영 데이터 삭제 위험.

**수정**: `rateLimits = sqliteTable('rate_limits', { userId, bucketMinute, count, lastUpdatedAt })` Drizzle 선언 추가, 복합 PK `(userId, bucketMinute)` + `idx_rate_limits_bucket` 인덱스 포함. 파일 상단 주석 "14 tables" 갱신 + "UPSERT 대상, Temporal 예외" 명시.

### 🔴 CR-4. `draft-loader.ts:111-116` ↔ `local-db.ts:115-122` — batch() 로컬/프로덕션 원자성 분기

**출처**: Pass 1 Surgeon / Pass 2 Architect — **2개 에이전트 동시 지적**

주석은 "원자적 적재 — 실패 시 전체 rollback" 이지만 로컬 wrapper 는 for-loop + 순차 run() (트랜잭션 없음). Cloudflare D1 production 은 atomic txn → 테스트 통과 ≠ 프로덕션 정합.

**재현**: 5번째 formula 에서 UNIQUE 위반 → 앞 4개 commit 된 채 throw. 재실행 시 INSERT OR IGNORE 로 skip 되지만 `nodesInserted` 집계 틀어짐 (거짓 메트릭).

**수정**: local-db wrapper 의 batch 메서드를 SQLite BEGIN/COMMIT/ROLLBACK 트랜잭션으로 감쌈. 또는 주석 수정 + 적재 실패 수동 cleanup 명시.

### 🔴 CR-5 (묶음). Pass 4 Contract — Golden 정의 / Fixture E2E 착시 / formulas status drift

**수정**: 각각 ADR 또는 명시적 이월 문서화. 5a는 교재 원문 대조 (교재 저작권은 진산님 "문제없음" 확정), 5b는 non-fixture 통합 테스트 1건 이상 추가, 5c는 ADR 작성.

## Devil's Advocate 시나리오 (종합)

**시나리오 A — 병렬 워커 enumeration**: 악성 유저 10개 브라우저 탭 → Cloudflare 가 다른 워커 인스턴스 라우팅 → UPSERT+SELECT race 로 한도 80~100/min 확장 → CR-2 결합 시 이틀 내 교재 전수 열거.

**시나리오 B — migration 무음 삼킴**: 운영자가 0013 마이그레이션 오탈자(컬럼명 오류) 배포. local-db 광범위 정규식이 삼켜 CLI "정상 종료" → 운영자 "적용 완료" 오인 → 실제 D1 미반영 → 다음 배치 터짐 (L3 무음 실패 = 서비스 사망).

**시나리오 C — Year 2 확장 복합 폭발**: loadDraft examId 누락(MJ-1) + BATCH_CONFIGS 시험특화 하드코딩(MJ-2) + constants exam_id 컬럼 부재 + pageRef "손해평가사 교재" 암묵 가정 — 네 수정이 단일 PR 동기화 필요. 하나 빠지면 Year 1 데이터 Year 2 쿼리에 섞임.

**시나리오 D — 운영자 교정 워크플로우 공백**: `prevent_nodes_update` 트리거로 오타 교정 불가 → 새 ID + SUPERSEDES 수동 생성 → Ontology Lock 위반 위험. Phase 2 착수 전 ADR 필수.

**시나리오 E — SDK 메모리 누수**: Stage 2.5/3 페이지 루프 안에서 `createAnthropicClient` 반복 호출 시 HTTP agent 수백 개 누적 → Node EventEmitter leak → 크래시.

**시나리오 F — status_transitions 동시성**: 두 reviewer 가 draft→review 동시 시도 → 둘 다 `fromStatus='draft'` 읽고 INSERT → 같은 노드에 review 레코드 2개. 트리거 2차 방어선 커버리지 미확인.

**시나리오 G — Claude 응답 코드블록 중복**: 교재가 마크다운 코드펜스 예시 포함 시 batch-processor 정규식 첫 매칭만 잡고 중간 잘림 → 유효 JSON 파싱되지만 nodes 누락 → validation 통과(최소 1건) → **silent data loss 로 적재**.
